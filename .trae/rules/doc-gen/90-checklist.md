# 90 · 生成自检清单（最终关卡）

> 文档输出前必须逐条核对本清单，**未通过项必须修正后才能交付**。
> 维护说明：10 / 20 / 30 / 40 中的「待补充」条目转为正式规则时，需同步追加到本清单与量化标准表。

## 固定校验项（始终生效）

### 背景与语境（00-context）

- [ ] 文档开头包含「项目背景」区块，且与 00-context.md 模板一致
- [ ] 文档类型（blog / tech）已明确，类型附加要求已满足
- [ ] 项目经历类文章亮点自然嵌入（问题→思考→方案），无显式标签（00-context 定位与写作基调）

### 语言风格（10-style）

- [ ] 全文简体中文，技术术语处理符合 S1
- [ ] 代码注释语言符合 S2
- [ ] 口吻与人称符合 S3（无「你/我们/大家」等对话式人称）
- [ ] 开头与段落无冗余铺垫性寒暄，符合 S4
- [ ] 术语密度与首次出现处理符合 S5
- [ ] 无情绪形容词（很棒、巧妙地、真香等），符合 S6
- [ ] 项目经历亮点自然嵌入，无「亮点/重点」标签，符合 S7

### 代码示例（20-code）

- [ ] 所有代码块带语言标签（C1）
- [ ] 示例可运行或省略处已显式标注（C2）

### 图表（30-diagram）

- [ ] 图表均有正文引用，非装饰性（D1）
- [ ] 全部文本化图表，无截图式图片（D2）

### 结构格式（40-format）

- [ ] blog 类型 frontmatter 字段与顺序合规（F3）
- [ ] slug 为中文且与 title 一致（F4）
- [ ] frontmatter 之后固定有 `## Table of contents` 占位（F5）
- [ ] 一级章节用中文数字，子章节用阿拉伯数字（F6）
- [ ] description 有具体论点与方向，无空泛套话（F7）
- [ ] 专栏（如有）series 格式正确、seriesOrder 递增（F8）

### 项目红线（00-context 强制约束）

- [ ] 涉及 UI 字符串时，已同步 zh.ts / en.ts / UIStrings 类型
- [ ] blog 类型已检查 frontmatter 合规与双语发布要求

## 量化标准速查

| 校验项 | 标准 | 来源 |
| ---- | ---- | ---- |
| 项目背景区块 | 100% 必含 | 40-F1 |
| 代码块语言标签 | 100% 覆盖 | 20-C1 |
| 图表正文引用 | 100% 覆盖 | 30-D1 |
| 简体中文正文 | 100%（术语除外） | 10-S1 |
| blog frontmatter 字段完整性 | 100% 覆盖（含专栏扩展） | 40-F3 |
| TOC 占位 | 100% 出现 | 40-F5 |
| description 密度达标 | 拒绝空泛套话 | 40-F7 |
| 情绪形容词 | 0 容忍 | 10-S6 |
