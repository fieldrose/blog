## 闭包和高阶函数

闭包让函数携带定义时的作用域，高阶函数让函数成为参数与返回值。JavaScript 中大量设计模式是这两个特性的直接产物：单例用闭包藏实例，策略用函数替代类，代理用高阶函数包装原函数，缓存与节流都靠闭包保存状态。

### 1. 闭包的形成与作用域链

#### 1.1 变量作用域与作用域链

```js
const scope = "global";

function outer() {
  const outerVar = "outer";

  function inner() {
    return [scope, outerVar];
  }

  return inner();
}

outer(); // ["global", "outer"]
```

- 作用域在函数定义时确定，属于词法作用域，调用位置不参与变量解析。
- 查找变量沿作用域链由内向外，命中即停止；每调用一次函数就创建一份新的局部变量。

#### 1.2 闭包的形成条件

```js
function createCounter() {
  let count = 0;

  return function () {
    count += 1;
    return count;
  };
}

const next = createCounter();
next(); // 1
next(); // 2
```

- 形成条件：函数嵌套、内层函数引用外层变量、内层函数在外层作用域之外被调用。
- 闭包保留的是变量环境本身，而不是某一时刻的副本，多次调用共享同一份 `count`。

#### 1.3 闭包与内存

```js
function attach() {
  const huge = new Array(1e6).fill(0);

  return function () {
    return huge.length;
  };
}
```

- 闭包延长了被引用变量的生命周期，大对象常驻堆内存会推高内存占用；释放依赖把引用置空、移除事件监听或清除定时器。
- V8 会做逃逸分析，未被引用的变量可能被回收，依赖该行为做内存管理不可靠。

### 2. 闭包的典型用途

#### 2.1 封装私有变量

```js
function createWallet(initial) {
  let balance = initial;

  return {
    deposit(amount) {
      if (amount <= 0) throw new RangeError("amount must be positive");
      balance += amount;
    },
    get balance() {
      return balance;
    },
  };
}
```

- 余额只能通过 `deposit` 修改，校验逻辑随数据一起封装，外部无法绕过。

#### 2.2 缓存（记忆化）

```js
function memoize(fn) {
  const cache = new Map();

  return function (key) {
    if (cache.has(key)) return cache.get(key);
    const value = fn(key);
    cache.set(key, value);
    return value;
  };
}
```

- `cache` 由闭包持有，外部无法篡改；只适合纯函数，无界缓存会持续增长，生产实现需要容量上限、TTL 或 `WeakMap`。

#### 2.3 延长变量寿命

```js
function report(message) {
  setTimeout(() => {
    console.log(message);
  }, 100);
}

report("done");
```

- 回调在 `report` 返回之后执行，仍能读到 `message`；事件监听与 Promise 回调依赖同一机制。

#### 2.4 循环中的闭包问题

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0); // 3 3 3
}
```

- `var` 只有函数作用域，三轮循环共享同一个 `i`，回调执行时循环已经结束。
- 改用 `let`，每轮迭代创建新的绑定：

```js
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0); // 0 1 2
}
```

| 方案 | 绑定来源 | 适用场景 |
| --- | --- | --- |
| `let` | 每轮迭代独立绑定 | 新代码首选 |
| IIFE | 函数调用创建新作用域 | ES5 环境、需要兼容旧语法 |
| 回调工厂 | 工厂参数保存当前值 | 回调逻辑较复杂时 |

### 3. 高阶函数

高阶函数指参数或返回值为函数的函数。JavaScript 中函数是一等对象，这使高阶函数成为最常用的抽象手段。

#### 3.1 作为参数

```js
function filter(list, predicate) {
  const result = [];
  for (const item of list) {
    if (predicate(item)) result.push(item);
  }
  return result;
}

filter([1, 2, 3, 4], (n) => n % 2 === 0); // [2, 4]
```

- 遍历骨架留在 `filter` 内，判断逻辑外置为参数，`map`、`filter`、`reduce`、`sort` 都是这一形态。

#### 3.2 作为返回值

```js
function makeLogger(prefix) {
  return (message) => console.log(`[${prefix}] ${message}`);
}

const warn = makeLogger("warn");
warn("cache miss"); // [warn] cache miss
```

- 返回函数把配置与执行分离，`prefix` 通过闭包固定；同一工厂可以生成多个互不干扰的实例。

#### 3.3 函数柯里化

```js
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {
      return fn.apply(this, args);
    }
    return (...rest) => curried.apply(this, [...args, ...rest]);
  };
}

const add = curry((a, b, c) => a + b + c);

add(1)(2)(3); // 6
add(1, 2)(3); // 6
```

- 实现依赖 `fn.length`，默认参数与剩余参数不会计入，参数个数不固定时通用实现容易误判。
- 用途是预置参数、生成领域专用函数，例如固定 `baseURL` 的请求函数。

#### 3.4 uncurrying

```js
Function.prototype.uncurrying = function () {
  const fn = this;
  return (target, ...args) => fn.apply(target, args);
};

const push = Array.prototype.push.uncurrying();
const arrayLike = { length: 0 };

push(arrayLike, "a");
arrayLike.length; // 1
```

- 把 `obj.method(args)` 转成 `method(obj, args)`，接收者变成普通参数，本质仍是借用方法；实际项目很少使用。

### 4. 常用高阶函数实现

#### 4.1 节流

```js
function throttle(fn, wait) {
  let last = 0;

  return function (...args) {
    const now = Date.now();
    if (now - last >= wait) {
      last = now;
      fn.apply(this, args);
    }
  };
}
```

- 在 `wait` 毫秒内最多执行一次，首次调用立即触发，闭包中的 `last` 保存上次执行时间；滚动、拖拽、`resize` 等高频事件适合该策略，需要头尾都触发时改用时间戳加定时器的双模式实现。

#### 4.2 防抖

```js
function debounce(fn, wait) {
  let timer = null;

  return function (...args) {
    clearTimeout(timer);
    timer = setTimeout(() => {
      fn.apply(this, args);
    }, wait);
  };
}
```

- 每次触发都重置计时器，连续触发只在停止后执行最后一次。
- 工程实现通常还会返回 `cancel` 与 `flush`，并在组件卸载时调用，避免回调访问已销毁的实例。

| 函数 | 触发时机 | 高频期间执行次数 | 典型场景 |
| --- | --- | --- | --- |
| 节流 | 每 `wait` 毫秒至多一次 | 与时长相关 | 滚动、拖拽 |
| 防抖 | 停止触发 `wait` 毫秒后 | 一次 | 搜索输入、表单校验 |

#### 4.3 分时函数

```js
function timeChunk(data, fn, count, interval) {
  let timer = null;

  const run = () => {
    const batch = data.splice(0, count);
    batch.forEach(fn);
    if (data.length === 0) clearInterval(timer);
  };

  return () => {
    timer = setInterval(run, interval);
  };
}
```

- 把大批量任务拆成每批 `count` 个，按 `interval` 分批执行，避免一次性长任务阻塞渲染；`splice` 会修改原数组，现代替代方案是 `requestIdleCallback` 与虚拟列表。

#### 4.4 惰性加载函数

```js
let addEvent = function (element, type, handler) {
  if (element.addEventListener) {
    addEvent = (element, type, handler) => {
      element.addEventListener(type, handler, false);
    };
  } else {
    addEvent = (element, type, handler) => {
      element.attachEvent(`on${type}`, handler);
    };
  }

  return addEvent(element, type, handler);
};
```

- 首次调用完成能力检测并重写自身，后续调用直接走已确定的分支，判断只发生一次。
- `attachEvent` 属于 IE 时代的兼容写法，该结构更多用于说明延迟决策的思路；当前环境下同一思路适用于按需加载重型模块：

```js
let loadChart = function () {
  return import("./chart.js").then((module) => {
    loadChart = () => Promise.resolve(module);
    return module;
  });
};
```

- 首次调用触发动态导入，之后复用已缓存的模块，避免重复请求。
