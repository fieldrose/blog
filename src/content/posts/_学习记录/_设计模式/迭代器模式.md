## 迭代器模式

迭代器模式提供一种方法顺序访问聚合对象中的各个元素，而不暴露该对象的内部表示。聚合对象负责存储，迭代器负责遍历，两者分离后，聚合对象可以更换内部数据结构，遍历逻辑也能独立演进。

### 1. 迭代器模式的作用与适用场景

模式解决的是「遍历」与「存储」耦合的问题。数组、链表、树、文件列表的遍历方式各不相同，如果让调用方直接操作内部结构，聚合对象的实现细节就会泄漏到业务代码中。

适用场景：

- 聚合对象内部结构复杂，需要对外提供多种遍历顺序，如正序、倒序、按条件过滤。
- 希望为数组、类数组、字面量对象、树形结构提供统一的遍历入口。
- 遍历过程需要中途停止，调用方要能决定迭代何时结束。
- 内部数据结构的变更不应影响已有的遍历代码。

在 JavaScript 语境下，数组自带 `forEach`、`map`、`for...of`，手写迭代器的场合已经不多。模式的价值体现在理解这些内建 API 的分工与局限，以及在没有内建能力时如何补一层封装。

### 2. forEach 与 jQuery each 的历史写法

```js
[1, 2, 3].forEach(function (item, index) {
  console.log(index, item);
});

// jQuery 1.x style, still visible in legacy pages
$.each([1, 2, 3], function (index, item) {
  console.log(index, item);
});
```

- `forEach` 属于内部迭代器：遍历规则由 `forEach` 自己决定，调用方只提供「对每个元素做什么」。
- 内部迭代器无法表达「找到目标就停」：`forEach` 忽略回调的返回值，`break` 也不作用于回调内部。
- jQuery 的 `$.each` 约定回调返回 `false` 时中止遍历，这是用返回值模拟控制流的补丁写法；该库在 3.x 之后逐步退出主流技术栈，写法仅作历史参照。

内部迭代器的收益是调用方便、职责单一，代价是迭代控制权交给被调用方。一旦出现「提前结束」「跳过部分元素」的需求，只能修改迭代器本身，或者换用外部迭代器。

### 3. 实现自己的迭代器

#### 3.1 内部迭代器

```js
function each(obj, callback) {
  const len = obj.length;

  for (let i = 0; i < len; i++) {
    // a false return value means "stop"
    if (callback.call(obj[i], obj[i], i) === false) {
      break;
    }
  }

  return obj;
}

each([1, 2, 3], function (item) {
  console.log(item);
});
```

实现只依赖 `length` 与数字下标，与元素类型无关，因此同一份 `each` 可以处理数组、`arguments`、`NodeList`。回调通过 `call` 绑定到当前元素，使 `this` 指向元素本身，便于在回调内访问元素属性。

#### 3.2 外部迭代器

```js
function Iterator(list) {
  let current = 0;

  return {
    isDone() {
      return current >= list.length;
    },
    next() {
      current += 1;
    },
    getCurrent() {
      return list[current];
    },
    length() {
      return list.length;
    },
  };
}

const iterator = Iterator([1, 2, 3]);

while (!iterator.isDone()) {
  console.log(iterator.getCurrent());
  iterator.next();
}
```

外部迭代器把「取当前值」「推进指针」「判断结束」拆成三个显式方法。调用方持有迭代器对象，用普通循环驱动，可以在任意位置插入 `break`、`continue` 或额外的业务判断。

#### 3.3 两者对比

| 维度 | 内部迭代器 | 外部迭代器 |
| --- | --- | --- |
| 控制权 | 迭代器内部 | 调用方 |
| 调用方式 | 传入回调函数 | 手动调用 `next` |
| 提前中止 | 依赖返回值约定 | 循环中直接 `break` |
| 多次遍历 | 每次重新调用 | 可持有多个迭代器实例 |
| 典型代表 | `forEach`、`$.each` | ES6 迭代器、`for...of` |

内部迭代器适合「每个元素做同一件事」的批量处理，代码短；外部迭代器适合需要交错遍历多个聚合对象、或遍历过程中频繁判断的场景。

### 4. 迭代类数组与字面量对象

类数组的核心特征是拥有 `length` 属性与连续的数字下标，`arguments`、`NodeList`、`HTMLCollection`、字符串都满足这一条件。

```js
function report() {
  each(arguments, function (item) {
    console.log(item);
  });
}

report("a", "b", "c");
```

字面量对象只要补齐 `length` 与下标，同样可以被同一实现处理：

```js
const fakeArray = { 0: "a", 1: "b", length: 2 };

each(fakeArray, function (item) {
  console.log(item);
});
```

普通对象没有 `length`，需要先取 `Object.keys`，或改用 `for...in` 配合 `hasOwnProperty` 过滤原型链属性。把两种形态混进一个 `each` 会让分支变多，按调用点区分更清晰：

```js
function eachObject(obj, callback) {
  Object.keys(obj).forEach((key) => {
    callback(obj[key], key);
  });
}
```

### 5. 倒序迭代器与中止迭代器

倒序遍历只需改变指针方向，其余结构与正序一致：

```js
function reverseEach(obj, callback) {
  for (let i = obj.length - 1; i >= 0; i--) {
    callback.call(obj[i], obj[i], i);
  }
}

reverseEach([1, 2, 3], function (item) {
  console.log(item); // 3 2 1
});
```

中止能力有两种实现。返回值约定最轻量，改造成本低：

```js
function each(obj, callback) {
  for (let i = 0; i < obj.length; i++) {
    if (callback(obj[i], i) === false) {
      return false;
    }
  }
  return true;
}
```

抛异常的方式可以穿透多层嵌套，但异常会吞掉真实的运行时错误，栈信息也难以定位，业务代码中不推荐。

```js
function stoppingEach(obj, callback) {
  try {
    for (let i = 0; i < obj.length; i++) {
      if (callback(obj[i], i) === false) {
        throw new Error("break");
      }
    }
  } catch (error) {
    if (error.message !== "break") {
      throw error;
    }
  }
}
```

现代写法直接把控制权交还给语言：`for...of` 的 `break` 与函数内的 `return` 都能自然终止遍历，不需要任何约定。

### 6. 应用举例：上传组件收集文件对象

上传控件通常有多个入口：按钮选择、拖拽区域、粘贴板。各入口把文件对象放进同一个队列，提交时统一收集。

```js
function UploadQueue() {
  const files = [];

  return {
    add(file) {
      files.push(file);
    },
    iterator() {
      let current = 0;

      return {
        isDone() {
          return current >= files.length;
        },
        next() {
          current += 1;
        },
        getCurrent() {
          return files[current];
        },
      };
    },
  };
}

const queue = UploadQueue();
queue.add({ name: "a.png", size: 1024 });
queue.add({ name: "b.png", size: 2048 });

const it = queue.iterator();

while (!it.isDone()) {
  const file = it.getCurrent();
  console.log(file.name, file.size);
  it.next();
}
```

队列只暴露 `add` 与迭代入口，`files` 数组不对外可见，调用方无法用 `push` 或直接改下标破坏内部状态。若外部确实需要数组方法，返回副本 `[...files]` 比返回原引用安全。

这类封装在项目中的判断依据是「谁会改数据」：只有队列自己写入时，只读迭代器就足以支撑外部消费；一旦外部需要随机访问或排序，直接暴露数组反而更简单。

### 7. 与 ES6 迭代协议的对应

ES6 把外部迭代器抽象为语言级协议：对象实现 `Symbol.iterator` 方法并返回带 `next()` 的迭代器，即为可迭代对象；`for...of`、展开运算符、解构、`Array.from` 都消费该协议。

```js
const queue = {
  files: [],
  add(file) {
    this.files.push(file);
  },
  [Symbol.iterator]() {
    let i = 0;
    const files = this.files;

    return {
      next() {
        return i < files.length
          ? { value: files[i++], done: false }
          : { value: undefined, done: true };
      },
    };
  },
};

for (const file of queue) {
  console.log(file.name);
}
```

手写版本的三个方法被收敛为一个 `next()`，返回值用 `{ value, done }` 表达同样的状态：

| 手写迭代器 | ES6 迭代协议 |
| --- | --- |
| `isDone()` | `next().done` |
| `getCurrent()` | `next().value` |
| `next()` 推进指针 | `next()` 返回下一项 |
| `while` 循环驱动 | `for...of` 驱动 |

`for...of` 在循环体内执行 `break`、`return` 或抛出异常时，会调用迭代器的 `return()` 方法做清理，这是协议为资源释放预留的钩子。生成器函数是创建迭代器的语法糖，涉及状态保存与协程语义，另篇处理。

理解手写版本之后，`for...of` 不再是黑盒，而是「取当前值、推进指针、判断结束」这三步的协议封装。
