## 代理模式

代理在调用方与本体之间插入一层，控制对本体对象的访问。代理与本体实现相同的接口，调用方察觉不到差异，差异体现在时机、次数与权限上：虚拟代理推迟开销，缓存代理复用结果，保护代理过滤调用，合并代理压缩请求数量。

### 1. 保护代理与虚拟代理

| 类型 | 控制目标 | 判断依据 | 前端常见形态 |
| --- | --- | --- | --- |
| 保护代理 | 访问权限 | 调用方身份、参数合法性 | 请求拦截器、权限守卫 |
| 虚拟代理 | 访问开销 | 本体是否就绪、是否需要即时创建 | 图片预加载、惰性加载 |
| 缓存代理 | 重复计算 | 参数是否命中缓存 | 记忆化函数 |
| 远程代理 | 位置差异 | 本体位于远端 | RPC 客户端、`fetch` 封装 |

- 保护代理在浏览器端很少单独实现，鉴权最终由服务端裁决；前端代理只负责提前拦截无效请求。
- 虚拟代理把开销大的操作延后，图片预加载、大组件渲染、富文本编辑器初始化都属于这一形态。
- 代理与本体接口一致是前提：接口不一致时，调用方需要知道持有的是哪一个，模式退化为普通封装。

### 2. 虚拟代理实现图片预加载

直接在 `img.src` 上设置大图，会出现空白等待与布局抖动。虚拟代理先用占位图占住位置，真实图片加载完成后替换：

```js
function createImage(placeholder) {
  const img = document.createElement("img");
  document.body.appendChild(img);
  img.src = placeholder;

  const loader = document.createElement("img");
  loader.onload = () => {
    img.src = loader.src;
  };
  loader.onerror = () => {
    img.src = "./error.png";
  };

  return {
    setSrc(src) {
      img.src = placeholder;
      loader.src = src;
    },
  };
}

const image = createImage("./loading.gif");
image.setSrc("./photo.jpg");
```

- 代理返回的 `setSrc` 与真实 `img` 的 `setSrc` 行为一致，调用方按普通图片使用。
- 加载时序由代理负责，本体（真实图片的下载）只承担资源获取。
- 错误分支需要显式处理，否则占位图会一直停留。
- 现代实现可直接使用 `loading="lazy"`、`srcset` 与骨架屏，代理结构仍适用于需要自定义替换时序或需要做统一埋点的场景。

### 3. 代理与本体接口的一致性

```ts
interface ImageLoader {
  setSrc(src: string): void;
}

function createProxyImage(real: ImageLoader, placeholder: string): ImageLoader {
  return {
    setSrc(src) {
      real.setSrc(placeholder);
      setTimeout(() => real.setSrc(src), 300);
    },
  };
}
```

- 用同一个 `interface` 约束代理与本体，编译期即可发现接口漂移。
- 代理缩小接口（去掉写方法、只暴露读方法）时，性质转成保护代理，调用方需要显式依赖更窄的类型。
- 代理扩大接口（增加统计、重试）会让调用方产生额外依赖，替换回本体时出现编译错误，属于接口不一致的代价。
- 运行时可以用鸭子类型兜底，但接口一致性主要由类型系统与约定维护。

### 4. 合并 HTTP 请求

同一帧内多次调用上传或查询接口时，逐个发请求会造成连接浪费。代理收集一个时间窗口内的参数，合并为一次请求后按标识分发结果：

```js
function createBatchRequest(request, wait = 50) {
  let queue = [];
  let timer = null;

  return function (id) {
    return new Promise((resolve, reject) => {
      queue.push({ id, resolve, reject });

      if (timer) {
        return;
      }

      timer = setTimeout(() => {
        const batch = queue;
        queue = [];
        timer = null;

        request(batch.map((item) => item.id))
          .then((resultMap) => {
            batch.forEach((item) => item.resolve(resultMap[item.id]));
          })
          .catch((err) => {
            batch.forEach((item) => item.reject(err));
          });
      }, wait);
    });
  };
}
```

- 代理把「逐个调用」的语义转成「批量调用」，外部接口仍是 `getFile(id) => Promise`。
- 时间窗口越大，合并率越高，首个请求的延迟也越大；窗口大小按业务容忍度设置，通常在一帧到几十毫秒之间。
- 整批失败时按批次的错误统一处理，需要逐项重试时应在业务层拆分后再调用代理。
- 返回值必须按 `id` 映射回各调用方，顺序与合并前的调用顺序无关。

### 5. 惰性加载

`Proxy` 的 `get` 陷阱可以把本体创建推迟到首次属性访问：

```js
function createLazy(loader) {
  let instance = null;

  return new Proxy(
    {},
    {
      get(target, prop) {
        if (!instance) {
          instance = loader();
        }
        const value = instance[prop];
        return typeof value === "function" ? value.bind(instance) : value;
      },
    }
  );
}

const player = createLazy(() => new VideoPlayer());
player.play();
```

- 构造 `VideoPlayer` 的开销（创建 DOM、申请解码器）直到第一次调用 `play` 才发生。
- 成员方法需要 `bind`，否则方法内部的 `this` 指向代理对象，访问私有字段会失败。
- `set`、`has`、`ownKeys` 等陷阱若未实现，写属性与遍历会作用在空的目标对象上，需要按用途补齐。
- 与动态 `import()` 结合，可以把模块下载也推迟到首次使用，代理层负责缓存载入后的模块。

### 6. 缓存代理

#### 6.1 计算结果缓存

```js
function createCacheProxy(fn) {
  const cache = new Map();

  return function (...args) {
    const key = JSON.stringify(args);

    if (cache.has(key)) {
      return cache.get(key);
    }

    const result = fn.apply(this, args);
    cache.set(key, result);
    return result;
  };
}

const heavyParse = createCacheProxy((text) => {
  // expensive transformation
  return text.split(",").map(Number);
});
```

- 参数序列化为键，要求参数可被稳定序列化；对象属性的顺序差异会降低命中率。
- 只适合纯函数，依赖当前时间、随机数或外部状态的计算不应缓存。
- 缓存无上限增长会造成内存泄漏，生产实现需要容量上限、TTL 或按引用回收的 `WeakMap`。
- 返回引用类型时需要确认调用方不会修改结果，否则缓存内容会被外部副作用污染。

#### 6.2 用高阶函数动态创建缓存代理

```js
function createProxyFactory(fn) {
  const cache = new Map();

  return new Proxy(fn, {
    apply(target, thisArg, args) {
      const key = JSON.stringify(args);

      if (cache.has(key)) {
        return cache.get(key);
      }

      const result = Reflect.apply(target, thisArg, args);
      cache.set(key, result);
      return result;
    },
  });
}

const multiply = createProxyFactory((...nums) =>
  nums.reduce((acc, n) => acc * n, 1)
);

multiply(2, 3); // 6
multiply(2, 3); // 6, served from cache
```

- `apply` 陷阱拦截调用，代理保留原函数的属性与 `name`，`instanceof` 与 `typeof` 结果不变。
- 工厂返回的代理共享同一份缓存，缓存策略可以替换为 LRU 而不影响业务函数。
- 键的拼接方式必须无歧义，`[1, 23]` 与 `[12, 3]` 用逗号拼接会得到同一个键，`JSON.stringify` 可以避免，但会丢失函数与 `undefined` 参数。
- 异步函数缓存的是 Promise，失败结果也会被缓存，需要区分成功与失败分别存储。

### 7. 其他代理变体

- 防火墙代理：拦截指定方法的调用，对应前端的请求拦截器、路由守卫与权限指令。
- 远程代理：把本地调用转发到远端对象，`fetch` 封装、GraphQL 客户端与 RPC 层都属于此类，本体是服务端对象。
- 写时复制代理：读操作共享本体，写操作先复制再修改，用于大对象的不可变更新与撤销栈。
- 这些变体的共同点是代理持有本体引用，在调用前后插入控制逻辑；差异只在插入的控制是权限、时机、缓存还是传输。
