## 代码重构

重构是在不改变外部行为的前提下调整内部结构。判断依据是阅读成本与修改成本，而不是行数。以下 11 组手法覆盖代码评审中出现频率最高的形态，改造前提是行为可验证：入口有测试，或能用固定输入跑出可对比的输出。

### 1. 提炼函数

一段代码需要注释才能说明用途时，它就该成为一个有名字的函数。

```js
// Before
function printOwing(invoice) {
  console.log("**** Customer Owes ****");
  let outstanding = 0;
  for (const order of invoice.orders) outstanding += order.amount;
  console.log(`name: ${invoice.customer}`);
  console.log(`amount: ${outstanding}`);
}

// After
function calculateOutstanding(invoice) {
  return invoice.orders.reduce((sum, order) => sum + order.amount, 0);
}

function printOwing(invoice) {
  console.log("**** Customer Owes ****");
  const outstanding = calculateOutstanding(invoice);
  console.log(`name: ${invoice.customer}`);
  console.log(`amount: ${outstanding}`);
}
```

提炼的判据是片段有独立语义且不依赖大量局部变量。需要传入八个参数才能完成提炼，说明它与原上下文仍耦合。

### 2. 合并重复的条件片段

同一段代码出现在 `if` 与 `else` 中，把它移到分支之外。

```js
// Before
function total(price, isMember) {
  if (isMember) {
    const base = price * 0.9;
    return base + 10;
  } else {
    const base = price;
    return base + 10;
  }
}

// After
function total(price, isMember) {
  const discounted = isMember ? price * 0.9 : price;
  return discounted + 10;
}
```

前提是两段代码完全一致且无副作用。合并后只剩差异部分，差异才是逻辑真正要表达的内容。

### 3. 把条件分支提炼成函数

复杂条件表达式的问题不是长，而是无法命名。

```js
// Before
function charge(date, quantity) {
  if (date.before(SUMMER_START) || date.after(SUMMER_END)) {
    return quantity * winterRate + winterServiceCharge;
  }
  return quantity * summerRate;
}

// After
function isSummer(date) {
  return !date.before(SUMMER_START) && !date.after(SUMMER_END);
}

function charge(date, quantity) {
  if (isSummer(date)) return quantity * summerRate;
  return quantity * winterRate + winterServiceCharge;
}
```

`isSummer` 可以单独测试，起始日与结束日两个边界值有了明确落点，条件里的双重否定随函数名消失。

### 4. 合理使用循环

重复的结构化代码可以用循环收敛，但循环只适用于「操作相同、仅数据不同」的场景。

```js
// Before
function sumSelected(data) {
  let sum = 0;
  if (data.a) sum += data.a;
  if (data.b) sum += data.b;
  if (data.c) sum += data.c;
  return sum;
}

// After
const FIELDS = ["a", "b", "c"];

function sumSelected(data) {
  return FIELDS.reduce((sum, key) => sum + (data[key] ?? 0), 0);
}
```

副作用不同、执行次数不同、错误处理不同的代码不应合并进同一个循环，否则其中一步失败时难以判断其余步骤是否执行。循环的收益是消除重复，不是消除代码。

### 5. 提前让函数退出代替嵌套条件

嵌套条件把异常路径写在前面，正常路径被推到最深层缩进。

```js
// Before
function getResult(user) {
  if (user) {
    if (user.active) {
      if (user.verified) {
        return compute(user);
      }
    }
  }
  return null;
}

// After
function getResult(user) {
  if (!user) return null;
  if (!user.active) return null;
  if (!user.verified) return null;
  return compute(user);
}
```

每个条件独立成行，新增前置条件时追加一行即可，不需要再套一层缩进。

### 6. 传对象替代过长参数列表

参数超过四个时，调用处的字面量无法自我解释，顺序错误也难被发现。

```ts
// Before
function createUser(
  name: string,
  age: number,
  email: string,
  phone: string,
  address: string,
  role: string
) {
  // ...
}

// After
interface CreateUserInput {
  name: string;
  age: number;
  email: string;
  phone?: string;
  address?: string;
  role: "admin" | "member";
}

function createUser(input: CreateUserInput) {
  const { name, age, email, role } = input;
  // ...
}
```

两个约束：函数内部不应修改传入对象；可选参数集中后，必填项需要在入口校验，类型系统无法区分「没传」与「传了 `undefined`」。

### 7. 减少参数数量

这里的处理是让参数本身消失：参数承载的信息若已存在于某个对象上，就不必重复传递。

```js
// Before
function drawRect(ctx, x, y, width, height, color, lineWidth) {
  ctx.strokeStyle = color;
  ctx.lineWidth = lineWidth;
  ctx.strokeRect(x, y, width, height);
}

// After
class Canvas {
  constructor(ctx) {
    this.ctx = ctx;
    this.width = ctx.canvas.width;
    this.height = ctx.canvas.height;
  }

  drawRect(rect, style) {
    Object.assign(this.ctx, style);
    this.ctx.strokeRect(rect.x, rect.y, rect.width, rect.height);
  }

  clear() {
    this.ctx.clearRect(0, 0, this.width, this.height);
  }
}
```

尺寸从画布对象读取，样式合并为一个配置对象。另一手段是拆分函数：同时接受「是否重试」「重试次数」「超时时间」的函数，通常承担了策略与执行两个职责。

### 8. 少用三目运算符

三目适合二元选择，嵌套后阅读顺序与执行顺序不一致，也无法在中间分支设断点。

```js
// Before
const label = user.isEmployee ? "员工" : user.isVip ? "VIP" : "普通";

// After
function getLabel(user) {
  if (user.isEmployee) return "员工";
  if (user.isVip) return "VIP";
  return "普通";
}
```

单层且两个分支都是简单表达式时保留三目，例如 `const text = count > 1 ? "items" : "item"`。分支中出现函数调用、可选链或多行表达式时改为 `if` 或提前返回。

### 9. 合理使用链式调用

链式调用让数据变换按执行顺序排列，适合纯数据管道，不适合副作用链。

```js
// Before
const names = [];
for (const user of users) {
  if (user.active) names.push(user.name.trim());
}

// After
const names = users
  .filter((user) => user.active)
  .map((user) => user.name.trim());
```

边界：

- 链条超过四步时拆出中间变量，否则单步调试需要临时改写表达式。
- 混入请求、写库等副作用后，异常定位落在整条链上而非具体步骤。
- 返回 `this` 的链式 API 把调用方与内部状态绑定，中途失败时对象处于部分更新状态，长链中的类型推断也容易退化。

### 10. 分解大型类

类的膨胀通常不是方法太多，而是职责太多。分解依据是变化原因。

```ts
// Before: pricing, persistence and notification share one class
class Order {
  calculateTotal() {}
  save() {}
  notify() {}
}

// After
class Order {
  constructor(pricing, repository, notifier) {
    Object.assign(this, { pricing, repository, notifier });
  }

  checkout() {
    const total = this.pricing.calculate(this.data);
    return this.repository.save({ ...this.data, total });
  }
}
```

`Order` 保留编排，计价、存储、通知各自独立。拆分后只剩一个方法且无内部状态的类，可以先用函数替代，出现第二个相关方法再升级为类。

### 11. 用 return 退出多重循环

`break` 只退出当前层，多重循环需要标志变量判断外层是否继续。

```js
// Before
function findUser(groups, id) {
  let found = null;
  for (const group of groups) {
    for (const user of group.users) {
      if (user.id === id) { found = user; break; }
    }
    if (found) break;
  }
  return found;
}

// After
function findUser(groups, id) {
  for (const group of groups) {
    for (const user of group.users) {
      if (user.id === id) return user;
    }
  }
  return null;
}
```

`return` 直接结束函数，标志变量与重复判断一并消失。若找到后还需继续处理，就把查找抽成独立函数，外层用返回值判断。标签语句 `break outer` 可读性低于函数提取，只在循环体很短且无需复用时使用。返回值语义在改造前后必须一致，`null` 还是 `undefined` 由调用方的既有判断决定。
