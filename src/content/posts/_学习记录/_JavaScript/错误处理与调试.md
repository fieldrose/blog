## 错误处理与调试

本篇覆盖错误的产生、传递与捕获：Error 的类型体系、`try/catch/finally` 的执行规则、全局兜底事件的边界，以及在浏览器中定位问题的调试手段。错误处理与调试属于同一问题的两端，前者是代码侧的防御，后者是运行时的取证。

### 1. 错误对象

#### 1.1 Error 与常见子类

`Error` 是所有错误的基类，实例包含 `message`、`name`、`stack` 三个核心属性，子类用于区分错误来源。

| 子类 | 典型触发场景 |
| --- | --- |
| `TypeError` | 对 `undefined` 取属性、调用非函数 |
| `ReferenceError` | 访问未声明变量 |
| `RangeError` | 数值越界、递归层数过深 |
| `SyntaxError` | `JSON.parse` 解析失败、`eval` 语法错误 |
| `URIError` | `decodeURIComponent` 参数非法 |

```js
const err = new TypeError("invalid payload");
err.name; // "TypeError"
err.message; // "invalid payload"
err.stack; // 调用栈字符串
```

- 自定义错误应继承 `Error` 并修正 `name`，便于按类型分支处理：

```js
class HttpError extends Error {
  constructor(status) {
    super(`HTTP ${status}`);
    this.name = "HttpError";
    this.status = status;
  }
}
```

- `stack` 不属于标准，但主流引擎均实现，生产环境需压缩后配合 sourcemap 还原。
- `instanceof` 在跨 iframe 时失效，因为两侧构造函数不同，此时改用 `name` 判断。

#### 1.2 throw 任意值与错误冒泡

`throw` 可以抛出任意值，但抛出非 `Error` 实例会丢失调用栈。

```js
function parse(text) {
  if (!text) throw "empty input"; // 不推荐
  return JSON.parse(text);
}
```

- 抛出字符串或对象时，`catch` 拿到的是原值，没有 `stack` 可供定位。
- 错误沿调用栈向上冒泡，直到被最近的 `try/catch` 捕获，未捕获则终止当前任务。
- 异步回调中的错误不会冒泡到外层同步 `try`，这是回调风格的主要缺陷，也是 `Promise` 与 `async/await` 要解决的问题。

### 2. try/catch/finally

#### 2.1 执行顺序

```js
function run() {
  try {
    return "try";
  } finally {
    console.log("finally");
  }
}
run(); // 先打印 finally，再返回 "try"
```

- `try` 中发生错误时跳过剩余语句进入 `catch`，`catch` 结束后进入 `finally`。
- `finally` 无论是否出错、是否 `return` 都会执行，常用于释放句柄、清理定时器。
- `try` 中的 `return` 先求值并暂存，`finally` 执行完毕后才真正返回。

#### 2.2 catch 绑定与 finally 的返回值影响

```js
try {
  JSON.parse("{");
} catch {
  // 可选绑定，不需要错误对象时省略括号
}

function f() {
  try {
    return 1;
  } finally {
    return 2; // 覆盖前一个返回值
  }
}
f(); // 2
```

- ES2019 起 `catch` 的参数可省略，只做分支处理时更简洁。
- `finally` 中的 `return` 会覆盖 `try` 或 `catch` 的结果，同时吞掉尚未抛出的异常。
- `finally` 中的 `throw` 同样优先，会替换原有错误，应避免在其中编写可能失败的逻辑。

### 3. 全局错误捕获

#### 3.1 window.onerror 与 error 事件

```js
window.addEventListener("error", (event) => {
  report({
    message: event.message,
    filename: event.filename,
    lineno: event.lineno,
    colno: event.colno,
    error: event.error,
  });
});
```

- 回调参数依次为消息、脚本地址、行号、列号、错误对象。
- `onerror` 返回 `true` 可阻止控制台默认输出，`addEventListener` 方式无法阻止。
- 跨源脚本的报错会被脱敏为 `Script error.`，需要脚本标签加 `crossorigin` 且响应头返回 `Access-Control-Allow-Origin`。
- 该事件在捕获阶段同时接收资源加载失败，此时 `event.target` 是元素而非 `window`。

#### 3.2 unhandledrejection 与资源加载错误

```js
window.addEventListener("unhandledrejection", (event) => {
  report({ reason: event.reason });
  // event.preventDefault(); // 阻止控制台输出
});
```

- 未被 `.catch` 处理的 `Promise` 拒绝会触发该事件，回调时机在微任务队列清空之后。
- `event.reason` 为拒绝值，可能是 `Error`，也可能是任意字符串或对象。
- 资源错误不冒泡，只能在捕获阶段监听：

```js
window.addEventListener(
  "error",
  (event) => {
    const el = event.target;
    if (el instanceof HTMLImageElement) report({ src: el.src });
  },
  true
);
```

### 4. 错误处理策略

#### 4.1 致命与非致命

- 致命错误破坏页面核心功能，如初始化失败、路由崩溃，应展示兜底 UI 并停止后续流程。
- 非致命错误只影响局部，如单条数据格式化失败、可选增强失效，记录后继续执行。
- 划分依据是错误是否可恢复，而不是异常类型本身，同一 `TypeError` 在不同上下文中的处置可以不同。
- 全局兜底只负责收集与降级，不能替代业务层的显式判断。

#### 4.2 上报、降级与避免吞掉错误

```js
try {
  renderChart(data);
} catch (err) {
  report(err);
  renderFallback(); // 降级渲染
}
```

- 上报内容包含消息、栈、用户标识、构建版本与页面路径，便于按版本聚合与回归验证。
- 上报本身要限流与采样，并用 `sendBeacon` 避免阻塞页面卸载。
- 空 `catch` 是反模式，至少记录日志或附带上下文重新抛出：

```js
try {
  save();
} catch (err) {
  throw new Error("save failed", { cause: err });
}
```

- `cause` 保留原始错误链，避免包装时丢失根因，读取时通过 `err.cause` 向下追溯。
- 降级路径要与主路径一样可测，否则兜底代码本身会成为新的故障点。

### 5. 调试技术

#### 5.1 console 系列

```js
console.table([{ id: 1, name: "a" }]);
console.group("request");
console.time("fetch");
console.timeEnd("fetch");
console.assert(res.ok, "request failed");
console.trace("call path");
```

- `console.table` 以表格展示数组或对象，适合校验列表数据的字段分布。
- `console.time` 与 `timeEnd` 用同名标签配对，适合粗粒度耗时定位。
- `console.trace` 输出调用栈，`console.dir` 展开对象属性而非字符串化。
- 生产构建应剔除调试语句，避免在控制台泄漏内部数据结构。

#### 5.2 断点与调用栈

- 条件断点：在 Sources 面板右键行号设置表达式，仅在条件成立时暂停。
- 日志断点：不暂停执行，直接输出表达式结果，适合循环内部观测。
- `debugger` 语句等价于断点，提交前必须移除或由构建阶段剔除。
- 调用栈面板可逐层查看作用域变量，`Async` 堆栈能跨越 `await` 还原异步链路。

#### 5.3 Performance 面板

- 录制后查看 Main 火焰图，长任务（超过 50ms）会带红色角标，直接影响交互响应。
- Bottom-Up 视图按自身耗时排序，用于识别真正的热点函数，而非调用次数最多的函数。
- 判定渲染问题时配合 Layers 与 Rendering 面板，查看重排、重绘与合成层分布。
- 先由 Lighthouse 定位异常指标，再用 Performance 下钻到具体调用，避免无目标录制。
