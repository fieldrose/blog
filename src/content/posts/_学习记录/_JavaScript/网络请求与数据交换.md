## Table of contents

## 网络请求与数据交换

本篇覆盖浏览器发起网络请求的几代 API 与数据格式：从 JSON 的解析边界，到 XMLHttpRequest 与 Fetch 的行为差异，再到同源策略与 CORS 的判定流程，最后给出 Beacon、WebSocket、SSE 的适用场景。

### 1. XML 与 JSON 概览

#### 1.1 XML 的用途与现状

XML 曾作为 Ajax 时代默认的数据格式，如今在浏览器端数据交换中基本被 JSON 取代，仅保留在 SOAP 接口、SVG、RSS 等特定场景。

#### 1.2 JSON 语法

JSON 是 JavaScript 对象字面量的严格子集，值只能是对象、数组、字符串、数字、`true`、`false`、`null`。

```json
{
  "id": 1,
  "tags": ["js", "http"],
  "profile": { "active": true, "score": null }
}
```

- 键必须用双引号包裹，单引号与无引号键非法。
- 不支持注释、尾随逗号、`undefined`、函数、`NaN`、`Infinity`。
- 日期没有原生类型，惯例用 ISO 8601 字符串传递，读取后自行转换。

### 2. JSON 解析与序列化

#### 2.1 JSON.parse 与 reviver

第二个参数 reviver 在解析过程中逐个访问键值对，用于类型恢复或字段过滤。

```js
const text = '{"createdAt":"2026-11-18T00:00:00Z","name":"post"}';
const data = JSON.parse(text, (key, value) => {
  if (key === "createdAt") return new Date(value);
  return value;
});
```

- reviver 自内向外调用，先访问叶子节点，再访问父节点。
- 返回 `undefined` 会删除该属性；数组元素返回 `undefined` 时变成 `null`。
- 传入非法字符串抛出 `SyntaxError`，错误信息包含出错位置，可用于输入校验。

#### 2.2 JSON.stringify 的 replacer 与 space

```js
const user = { name: "Mimas", age: 30, token: "secret" };

JSON.stringify(user, ["name", "age"]); // {"name":"Mimas","age":30}

JSON.stringify(user, (key, value) =>
  key === "token" ? undefined : value
);

JSON.stringify(user, null, 2); // 两个空格缩进
```

- replacer 为数组时是白名单，只保留列出的键；为函数时按返回值替换，返回 `undefined` 则删除。
- space 为数字时上限 10 个空格，为字符串时取其前 10 个字符，仅影响可读性。
- `toJSON` 方法优先于 replacer，`Date` 内置了 `toJSON`，因此会被序列化为 ISO 字符串。

#### 2.3 循环引用与不可序列化值

```js
const node = { name: "root" };
node.self = node;

// JSON.stringify(node); // TypeError: Converting circular structure to JSON
```

- 循环引用直接抛 `TypeError`，需要先用 `WeakSet` 标记已访问对象再手写遍历。
- `undefined`、函数、`Symbol` 作为对象属性时被丢弃，作为数组元素时变成 `null`。
- `NaN`、`Infinity` 序列化为 `null`；`Map`、`Set`、`RegExp` 退化为 `{}`，需要自定义 `toJSON` 才能保留结构。

### 3. XMLHttpRequest

#### 3.1 基本流程

```js
const xhr = new XMLHttpRequest();
xhr.open("GET", "/api/posts");
xhr.setRequestHeader("Accept", "application/json");
xhr.onload = () => {
  if (xhr.status >= 200 && xhr.status < 300) {
    console.log(JSON.parse(xhr.responseText));
  }
};
xhr.send();
```

- `open` 只做初始化，`send` 才真正发起请求。
- `readyState` 从 0 推进到 4，旧代码监听 `readystatechange`，现代写法直接用 `onload`。
- 默认只对同源请求携带 cookie，跨源行为受 `withCredentials` 控制。

#### 3.2 请求头与响应头

```js
xhr.getResponseHeader("Content-Type");
xhr.getAllResponseHeaders(); // "content-type: application/json\r\n..."
```

- `setRequestHeader` 必须在 `open` 之后、`send` 之前调用。
- `Host`、`Origin`、`Cookie` 等头由浏览器控制，脚本无法直接修改。
- 跨源响应只有被 `Access-Control-Expose-Headers` 列出的字段才能被脚本读取。

#### 3.3 GET/POST、超时与进度事件

```js
const xhr = new XMLHttpRequest();
xhr.open("POST", "/api/posts");
xhr.setRequestHeader("Content-Type", "application/json");
xhr.timeout = 5000;
xhr.upload.onprogress = (e) => {
  if (e.lengthComputable) console.log(e.loaded / e.total);
};
xhr.onload = () => { /* ... */ };
xhr.ontimeout = () => { /* ... */ };
xhr.send(JSON.stringify({ title: "post" }));
```

- `upload` 上的进度事件对应上传阶段，`xhr.onprogress` 对应下载阶段。
- 超时触发 `ontimeout`，网络中断触发 `onerror`，两者都不会进入 `onload`。
- `lengthComputable` 为 `false` 时表示总长度未知，进度比例不可计算。

### 4. 跨源资源共享

#### 4.1 同源策略

同源要求协议、域名、端口三者完全一致。跨源请求本身可以发出，但响应默认不可读，这层限制由浏览器执行，服务端无法绕过。

- `document.domain` 已废弃，不再作为降级手段。
- 图片、脚本、样式等资源加载不受同源限制，但脚本无法读取其内容。
- `postMessage` 配合 `targetOrigin` 是跨窗口通信的替代路径。

#### 4.2 简单请求与预检请求

| 条件 | 简单请求 | 需预检 |
| --- | --- | --- |
| 方法 | `GET`、`HEAD`、`POST` | `PUT`、`DELETE`、`PATCH` 等 |
| 请求头 | `Accept`、`Accept-Language` 等白名单 | 自定义头 |
| `Content-Type` | `text/plain`、`multipart/form-data`、`application/x-www-form-urlencoded` | `application/json` |

```js
fetch("/api/posts", {
  method: "PUT",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ title: "post" }),
});
```

- 非简单请求先发 `OPTIONS` 预检，服务器以 `Access-Control-Allow-Methods`、`Access-Control-Allow-Headers` 回应。
- `Access-Control-Max-Age` 控制预检结果的缓存时长，减少重复探测。
- 预检失败时真实请求不会发出，控制台只给出 CORS 提示，没有状态码可读。

#### 4.3 凭证模式

- `credentials: "omit"` 不携带凭证，`"same-origin"` 为默认值，`"include"` 跨源也携带 cookie。
- 使用 `include` 时，服务器必须返回 `Access-Control-Allow-Credentials: true`，且 `Access-Control-Allow-Origin` 不能为 `*`。
- XHR 对应写法是 `xhr.withCredentials = true`，两种 API 的语义一致。

### 5. Fetch API

#### 5.1 Request、Response 与 Headers

```js
const req = new Request("/api/posts", {
  method: "POST",
  headers: new Headers({ "Content-Type": "application/json" }),
  body: JSON.stringify({ title: "post" }),
});

const res = await fetch(req);
const data = await res.json();
```

- `Response.body` 是 `ReadableStream`，可用于流式读取大响应。
- 响应体只能消费一次，`json`、`text`、`arrayBuffer` 互斥，需要复用时先 `clone()`。
- `Headers` 自动规范化键名大小写，`set` 覆盖同名字段，`append` 追加。

#### 5.2 状态码与 ok

```js
const res = await fetch("/api/posts/404");
console.log(res.status, res.ok); // 404 false
```

- Fetch 只在网络层失败时 reject，HTTP 4xx / 5xx 仍然 resolve。
- 业务判断必须显式检查 `res.ok` 或 `res.status`，不能只依赖 `catch`。
- `redirect: "manual"` 时拿到 `opaqueredirect` 响应，用于拦截跳转；`status` 为 0。

#### 5.3 错误处理与 AbortController

```js
const controller = new AbortController();
const timer = setTimeout(() => controller.abort(), 5000);

try {
  const res = await fetch("/api/slow", { signal: controller.signal });
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return await res.json();
} catch (err) {
  if (err.name === "AbortError") { /* 取消分支 */ }
  throw err;
} finally {
  clearTimeout(timer);
}
```

- 主动取消后 `fetch` 以 `AbortError` reject，需要与网络错误分开处理。
- 同一 signal 可取消多个请求，`AbortSignal.timeout(ms)` 提供了原生的超时写法。
- 相对 XHR，Fetch 没有上传进度事件，需要进度时仍要回到 XHR 或改用流式上传。

### 6. 其他通信方式与选型

#### 6.1 Beacon

```js
navigator.sendBeacon("/log", JSON.stringify({ event: "unload" }));
```

- 用于页面卸载时的埋点上报，请求由浏览器排队发送，不阻塞卸载流程。
- 只支持 POST，无法读取响应，体量通常限制在 64KB 以内。

#### 6.2 WebSocket 与 SSE

```js
const ws = new WebSocket("wss://example.com/feed");
ws.onmessage = (e) => console.log(e.data);
```

- WebSocket 为全双工，适合聊天、协作编辑等双向高频场景，需要服务端协议支持。
- SSE 基于 HTTP 单向推送，浏览器自动重连，适合通知、行情等服务器到客户端的数据流。

#### 6.3 选型

| 方式 | 方向 | 协议 | 典型场景 |
| --- | --- | --- | --- |
| Fetch / XHR | 请求-响应 | HTTP | 常规 CRUD |
| Beacon | 单向发送 | HTTP POST | 卸载埋点 |
| WebSocket | 双向 | ws / wss | 实时协作 |
| SSE | 服务器到客户端 | HTTP | 推送通知 |

- 一次性数据获取优先 Fetch，需要取消、超时或流式读取时同样选 Fetch。
- 只有需要上传进度或维护极旧环境时才回退 XHR。
- 高频双向交互用 WebSocket，单向推送优先 SSE，其重连与事件语义由浏览器托管。
