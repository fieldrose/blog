## 迭代器与生成器

本篇覆盖迭代协议、自定义迭代器、生成器函数的执行模型，以及提前终止时的清理语义。`for-of`、展开运算符、解构、`Map`/`Set` 构造与 `Promise.all` 都建立在同一套协议之上，理解协议比记住语法更重要。

### 1. 迭代与迭代器模式

#### 1.1 迭代器模式

迭代器模式把遍历逻辑从数据结构中剥离为独立对象，调用方只依赖 `next()`，不感知底层是数组、链表还是树。

```js
const iterator = {
  data: [1, 2, 3],
  index: 0,
  next() {
    const done = this.index >= this.data.length;
    return done
      ? { value: undefined, done: true }
      : { value: this.data[this.index++], done: false };
  },
};
// ...
```

- 遍历状态保存在迭代器内部，多个迭代器可以并行遍历同一份数据而互不干扰。
- 调用方不需要知道长度、索引或节点指针，只按 `done` 判断结束。

#### 1.2 可迭代协议与迭代器协议

两个协议分别约束「对象能否被遍历」与「迭代器如何产出值」。

| 协议 | 约定 | 作用 |
| --- | --- | --- |
| 可迭代协议 | 对象或其原型链上存在 `[Symbol.iterator]()` | 允许 `for-of`、展开、解构消费 |
| 迭代器协议 | 返回对象包含 `next()`，产出 `{ value, done }` | 定义单次推进的语义 |

```js
const iterable = {
  [Symbol.iterator]() {
    let i = 0;
    return {
      next: () =>
        i < 3 ? { value: i++, done: false } : { value: undefined, done: true },
    };
  },
};
// ...
```

- `[Symbol.iterator]()` 每次调用都应返回新的迭代器，否则多次遍历会共享状态。
- `done: true` 之后的 `value` 不再参与消费，后续 `next()` 应持续返回 `done: true`。
- 支持提前终止的迭代器还可以实现 `return()`，可选实现 `throw()`。

#### 1.3 内置可迭代对象

数组、字符串、`Map`、`Set`、`TypedArray`、`arguments`、`NodeList` 与生成器对象都实现了可迭代协议。

```js
const [first, second] = new Set([1, 2, 3]);
const chars = [..."abc"];
const entries = [...new Map([["a", 1]])];
// ...
```

- 普通对象没有 `Symbol.iterator`，直接 `for-of` 会抛 `TypeError`，需要 `Object.keys`、`Object.entries` 或自定义迭代器。
- 类数组对象只有 `length` 与索引，不等于可迭代对象；`Array.from` 对两者都能处理。

### 2. 自定义迭代器

#### 2.1 实现 Symbol.iterator

```js
class Range {
  constructor(start, end) {
    this.start = start;
    this.end = end;
  }

  [Symbol.iterator]() {
    let current = this.start;
    const end = this.end;
    return {
      next() {
        if (current > end) return { value: undefined, done: true };
        return { value: current++, done: false };
      },
      [Symbol.iterator]() {
        return this;
      },
    };
  }
}

for (const n of new Range(1, 3)) {
  // 1 2 3
}
```

- 迭代状态放在闭包里，实例本身不持有游标，因此可以重复遍历。
- 迭代器自身实现 `[Symbol.iterator]()` 返回 `this`，符合「迭代器也是可迭代对象」的惯例。

#### 2.2 可迭代对象与迭代器分离

把 `[Symbol.iterator]()` 写成返回 `this`，对象就退化为一次性迭代器，第二次遍历直接结束。

```js
const once = {
  data: [1, 2],
  index: 0,
  [Symbol.iterator]() {
    return this;
  },
  next() {
    if (this.index >= this.data.length) return { value: undefined, done: true };
    return { value: this.data[this.index++], done: false };
  },
};

console.log([...once]); // [1, 2]
console.log([...once]); // []
```

- 需要多次遍历的类型应分离「可迭代对象」与「迭代器」两个角色，每次 `[Symbol.iterator]()` 新建迭代器。
- 只消费一次的场景（流、游标、生成器）可以让两者合一，但要在命名与接口上体现一次性语义。

### 3. 生成器基础

#### 3.1 function* 与生成器对象

```js
function* gen() {
  yield 1;
  yield 2;
  return 3;
}

const it = gen();
console.log(it.next()); // { value: 1, done: false }
console.log(it.next()); // { value: 2, done: false }
console.log(it.next()); // { value: 3, done: true }
```

- 调用生成器函数不执行函数体，只创建生成器对象；执行从第一次 `next()` 开始。
- 生成器对象同时是迭代器与可迭代对象，`[Symbol.iterator]()` 返回自身。
- `return` 的值只出现在最后一次 `{ done: true }` 的 `value` 中，`for-of` 会忽略它。

#### 3.2 yield 的暂停与恢复

```js
function* steps() {
  console.log("enter");
  const a = yield 1;
  console.log("resume with", a);
  yield 2;
}

const it = steps();
it.next(); // enter -> { value: 1, done: false }
it.next("x"); // resume with x -> { value: 2, done: false }
```

- `yield` 会保存局部变量与执行位置，把控制权交还调用方，下一次 `next()` 从暂停点继续。
- 生成器是惰性的，函数体在需要时才推进，适合表达无限序列与按需计算。

```js
function* naturals() {
  let n = 0;
  while (true) yield n++;
}

const it = naturals();
console.log(it.next().value, it.next().value); // 0 1
```

- 无限生成器只有在调用方截断或主动终止时才会结束，`[...naturals()]` 会无限循环。

### 4. 生成器进阶

#### 4.1 next 传值

`next(value)` 的参数会成为上一个 `yield` 表达式的返回值。第一次 `next()` 没有对应的挂起点，参数被丢弃。

```js
function* echo() {
  const x = yield "first";
  const y = yield x * 2;
  return x + y;
}

const it = echo();
it.next(); // { value: "first", done: false }
it.next(3); // { value: 6, done: false }
it.next(10); // { value: 13, done: true }
```

- 传值机制让生成器成为双向通道：向外产出值，向内接收输入。
- 首次 `next()` 的参数会被忽略，这是编写协程式代码时最容易出错的位置。

#### 4.2 yield* 委托

```js
function* inner() {
  yield 2;
  yield 3;
}

function* outer() {
  yield 1;
  yield* inner();
  yield 4;
}

console.log([...outer()]); // [1, 2, 3, 4]
```

- `yield*` 可委托任意可迭代对象，包括数组、字符串、`Set` 与其他生成器。
- 委托期间 `next`、`throw`、`return` 都会转发给被委托的迭代器，其返回值成为 `yield*` 表达式的值。

#### 4.3 生成器作为默认迭代器

```js
class Tree {
  constructor(value, children = []) {
    this.value = value;
    this.children = children;
  }

  *[Symbol.iterator]() {
    yield this.value;
    for (const child of this.children) {
      yield* child;
    }
  }
}

const tree = new Tree(1, [new Tree(2), new Tree(3)]);
console.log([...tree]); // [1, 2, 3]
```

- 用生成器实现 `Symbol.iterator` 可以省略手写 `next` 与游标变量，代码结构与遍历语义一致。
- 递归结构用 `yield*` 展开子树，栈深度随层级线性增长，深层嵌套需要评估上限。

### 5. 提前终止

#### 5.1 return 与 finally

`for-of` 中的 `break`、`return` 与异常都会调用迭代器的 `return()`。生成器对象已实现该方法，会触发 `finally` 块。

```js
function* resource() {
  try {
    yield "acquired";
    yield "in use";
  } finally {
    // release resource here
    console.log("released");
  }
}

for (const step of resource()) {
  if (step === "acquired") break;
}
// released
```

- `return()` 让生成器在挂起点结束并执行 `finally`，是文件句柄、锁、订阅等资源的清理位置。
- 如果 `finally` 中再次 `yield`，生成器不会立即结束，调用方需要再推进一次才能完成清理。

#### 5.2 throw

```js
function* guarded() {
  try {
    yield 1;
  } catch (err) {
    console.log("caught", err.message);
  }
}

const it = guarded();
it.next();
it.throw(new Error("boom")); // caught boom -> { value: undefined, done: true }
```

- `throw(err)` 在挂起的 `yield` 位置抛出异常，生成器内部有 `try/catch` 时可以捕获并继续。
- 未捕获时异常冒泡到调用方，生成器进入完成状态，之后 `next()` 只返回 `{ done: true }`。
- `return(value)` 与 `throw(err)` 都是外部结束生成器的手段，区别在于内部是否经过异常路径。
