## 代理与反射

本篇覆盖 `Proxy` 的创建方式、常用捕获器与不变式、可撤销代理、几种典型代理模式，以及代理无法覆盖的边界。`Reflect` 是捕获器内部承载默认行为的配套 API，两者通常成对出现。

### 1. 代理基础

#### 1.1 new Proxy 与转发

`new Proxy(target, handler)` 返回一个包装对象，默认把所有内部方法转发给 `target`。

```js
const target = { name: "Mimas" };
const proxy = new Proxy(target, {});

console.log(proxy.name); // Mimas
proxy.name = "Other";
console.log(target.name); // Other
```

- `handler` 为空对象时，代理与目标的读写行为一致，但两者不是同一个对象，`proxy !== target`。
- 代理不会复制目标，所有状态仍在 `target` 上，修改任一侧都会反映到另一侧。
- `Object.keys`、`in`、`delete` 等操作同样经过代理的内部方法，可以被拦截。

#### 1.2 捕获器与 Reflect

每个捕获器对应一个内部方法，`Reflect` 提供同名方法承载默认行为。

```js
const handler = {
  get(target, property, receiver) {
    return Reflect.get(target, property, receiver);
  },
  set(target, property, value, receiver) {
    return Reflect.set(target, property, value, receiver);
  },
};

const proxy = new Proxy({ count: 0 }, handler);
proxy.count++;
// ...
```

- 捕获器内直接用 `target[property]` 会丢失 `receiver`，`Reflect.get`/`Reflect.set` 能保留原型链上的访问器语义。
- 捕获器的返回值必须符合内部方法的约定：`get` 返回任意值，`set`、`deleteProperty`、`has` 返回布尔值。
- 忘记 `return` 会让所有写入返回 `undefined`，在严格模式下触发 `TypeError`。

#### 1.3 代理与目标的关系

代理是目标之上的转发层，反射操作在代理上执行时，`receiver` 通常是代理本身。

```js
const target = {
  get double() {
    return this.value * 2;
  },
  value: 1,
};
const proxy = new Proxy(target, {
  get(t, key, receiver) {
    return Reflect.get(t, key, receiver);
  },
});

console.log(proxy.double); // 2，getter 中的 this 是 proxy
```

- 访问器中的 `this` 指向 `receiver`，因此通过代理读取时，getter 内部的属性访问也会再次进入捕获器。
- 递归捕获器需要避免无限递归，读操作必须落在 `target` 或使用 `Reflect`。

### 2. 常用捕获器

#### 2.1 get、set 与 has

```js
const handler = {
  get(target, key, receiver) {
    if (key === "secret") throw new Error("denied");
    return Reflect.get(target, key, receiver);
  },
  set(target, key, value, receiver) {
    if (typeof value !== "number") return false;
    return Reflect.set(target, key, value, receiver);
  },
  has(target, key) {
    return key.startsWith("_") ? false : Reflect.has(target, key);
  },
};

const proxy = new Proxy({ secret: 1, _internal: 2 }, handler);
// ...
```

- `set` 返回 `false` 时，严格模式下的赋值语句抛出 `TypeError`，非严格模式静默失败。
- `has` 拦截 `in` 操作符，不拦截 `Object.hasOwn` 与属性读取。
- `get` 中的异常会直接抛给调用方，适合做访问控制与只读视图。

#### 2.2 deleteProperty 与 ownKeys

```js
const proxy = new Proxy(
  { a: 1, _b: 2 },
  {
    deleteProperty(target, key) {
      if (String(key).startsWith("_")) return false;
      return Reflect.deleteProperty(target, key);
    },
    ownKeys(target) {
      return Reflect.ownKeys(target).filter((k) => !String(k).startsWith("_"));
    },
  },
);

console.log(Object.keys(proxy)); // ["a"]
```

- `ownKeys` 影响 `Object.keys`、`Object.getOwnPropertyNames`、`for-in` 等枚举入口，但不会改变属性本身的可枚举性。
- 过滤键时，`getOwnPropertyDescriptor` 也应返回一致结果，否则 `Object.keys` 会因描述符缺失而报错。

#### 2.3 apply 与 construct

```js
function sum(a, b) {
  return a + b;
}

const wrapped = new Proxy(sum, {
  apply(target, thisArg, args) {
    return Reflect.apply(target, thisArg, args) * 2;
  },
  construct(target, args, newTarget) {
    return Reflect.construct(target, args, newTarget);
  },
});

console.log(wrapped(1, 2)); // 6
```

- `apply` 拦截普通调用与 `Function.prototype.call`/`apply`，`construct` 拦截 `new`。
- `construct` 的返回值必须是对象，否则抛 `TypeError`；`newTarget` 用于保持原型链与 `new.target` 语义。
- 只有可调用对象才能作为 `apply` 的目标，只有构造函数才能作为 `construct` 的目标。

#### 2.4 捕获器不变式

代理必须与目标的内部状态保持一致，违反不变式会直接抛 `TypeError`。

```js
const frozen = Object.freeze({ a: 1 });
const proxy = new Proxy(frozen, {
  get() {
    return 2; // TypeError: 目标属性只读且不可配置
  },
});
// ...
```

- 目标上不可配置、不可写的数据属性，`get` 必须返回相同值。
- `ownKeys` 必须包含目标全部不可配置属性，且结果长度与目标一致。
- 不变式保证代理不能被用来伪造不可配置属性的状态，是引擎层面的安全约束。

### 3. 可撤销代理

`Proxy.revocable(target, handler)` 返回代理与撤销函数，调用 `revoke()` 后代理永久失效。

```js
const { proxy, revoke } = Proxy.revocable({ name: "Mimas" }, {});

console.log(proxy.name); // Mimas
revoke();
// proxy.name; // TypeError: Cannot perform 'get' on a proxy that has been revoked
```

- 撤销只切断代理与目标之间的连接，目标对象本身仍可正常使用。
- 撤销只能执行一次，重复调用不会抛错，但代理不会恢复。
- 适合把能力临时交给外部代码：组件卸载、插件停用、沙箱关闭后统一收回访问权。

### 4. 代理模式

#### 4.1 跟踪属性访问与隐藏属性

```js
function createTracker(target) {
  const seen = [];
  return new Proxy(target, {
    get(t, key, receiver) {
      seen.push(key);
      return Reflect.get(t, key, receiver);
    },
  });
  // 可另暴露 seen 的读取入口
}

const tracked = createTracker({ a: 1, b: 2 });
tracked.a;
tracked.b;
```

- 代理可以在读取路径上记录键名，用于调试、依赖收集与埋点。
- 隐藏属性依赖 `has`、`ownKeys`、`getOwnPropertyDescriptor` 三者口径一致，只改一个会暴露不一致。
- 对外暴露的代理接口应封闭，避免 `seen` 数组被外部改写。

#### 4.2 属性验证与函数参数验证

```js
const user = new Proxy(
  {},
  {
    set(target, key, value) {
      if (key === "age" && !Number.isInteger(value)) return false;
      return Reflect.set(target, key, value);
    },
  },
);

function createApi(fn) {
  return new Proxy(fn, {
    apply(target, thisArg, args) {
      if (args.some((arg) => typeof arg !== "number")) {
        throw new TypeError("expect numbers");
      }
      return Reflect.apply(target, thisArg, args);
    },
  });
}
// ...
```

- `set` 验证适合约束数据结构，返回 `false` 由调用方的严格模式决定是否报错。
- `apply` 验证适合为第三方回调加边界检查，不污染原函数实现。
- 验证失败应给出明确错误信息，避免返回 `false` 后静默失败。

#### 4.3 数据绑定与可观察对象

```js
function reactive(target, onChange) {
  return new Proxy(target, {
    set(t, key, value, receiver) {
      const old = t[key];
      const ok = Reflect.set(t, key, value, receiver);
      if (ok && old !== value) onChange(key, old, value);
      return ok;
    },
  });
}

const state = reactive({ count: 0 }, (key, oldValue, value) => {
  console.log(`${key}: ${oldValue} -> ${value}`);
});

state.count = 1; // count: 0 -> 1
```

- 响应式系统的入口是 `set` 与 `get`：写入时派发更新，读取时收集依赖。
- 嵌套对象需要在 `get` 中递归包装，数组还需要处理索引与长度变更。
- 代理负责拦截，调度与副作用管理由框架层实现。

### 5. 代理的局限

#### 5.1 性能开销

- 每次属性访问都要经过捕获器与 `Reflect` 转发，热路径上的开销高于直接读写。
- 代理的代理会叠加转发层，调用栈变深，性能分析与错误定位都更困难。
- 对高频访问的数据结构做透明包装前应先测量，避免把开销放进渲染循环或事件处理主路径。

#### 5.2 this 绑定

```js
const target = {
  name: "Mimas",
  greet() {
    return this.name;
  },
};

const proxy = new Proxy(target, {});
const greet = proxy.greet;
// greet(); // TypeError: this 为 undefined（严格模式）
```

- 通过代理调用方法时，`this` 是代理而不是目标；方法被取出单独调用会丢失绑定。
- 捕获器中应把 `receiver` 传给 `Reflect`，否则访问器与继承链的行为会偏离直接访问。
- 对依赖 `this` 的内部方法，可以在 `get` 中返回绑定到目标的函数，代价是每次读取都创建新函数。

#### 5.3 无法拦截的内部槽

内置对象的部分操作直接访问内部槽，绕过代理。

```js
const map = new Proxy(new Map(), {
  get(target, key) {
    const value = target[key];
    return typeof value === "function" ? value.bind(target) : value;
  },
});

map.set("a", 1);
console.log(map.get("a")); // 1
```

- `Map`、`Set` 的方法在 `this` 不是真实实例时抛 `TypeError`，需要在 `get` 中显式绑定目标。
- `size`、`Date` 的时间值、`RegExp` 的 `lastIndex` 等状态不经过普通属性访问路径，代理无法感知其变化。
- 这类对象更适合用包装对象暴露受限方法，而不是试图用代理做完全透明的替换。
