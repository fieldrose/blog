## Table of contents

## 变量与内存

本篇讨论 JavaScript 的数据存放方式与运行时的内存结构：值如何被复制与传递，标识符如何沿作用域链解析，声明如何被提升，垃圾回收器依据什么判断对象存活，以及工程上如何避免长期占用内存。这些机制是理解闭包、原型和性能问题的前置条件。

### 1. 原始值与引用值

ECMAScript 的变量是松散类型的，保存的值分为原始值（Undefined、Null、Boolean、Number、String、Symbol、BigInt）和引用值（对象）。原始值按值访问，引用值保存的是指向堆内存中对象的引用，变量本身只持有地址。赋值、比较、传参的行为差异全部源于这一点。

#### 1.1 动态属性

引用值可以随时增删改属性，原始值不能携带属性。对原始值执行属性赋值时，非严格模式静默失败，严格模式抛出 `TypeError`。读取原始值的属性看似成功，实际是引擎临时创建包装对象后立即销毁。

```js
const user = { name: "Mimas" };
user.age = 26;
console.log(user.age); // 26

const name = "Mimas";
name.age = 26;
console.log(name.age); // undefined，赋值被丢弃
```

#### 1.2 复制值

原始值复制的是独立副本，修改副本不影响原变量。引用值复制的是同一个地址，两个变量指向堆中的同一对象，任一侧的成员修改对另一侧可见。

```js
let a = 1;
let b = a;
b = 2;
console.log(a); // 1

const o1 = { value: 1 };
const o2 = o1;
o2.value = 2;
console.log(o1.value); // 2
```

#### 1.3 传递参数

所有参数都按值传递。传入原始值时复制其值；传入对象时复制的是引用的副本，函数内部可以修改对象的成员，但把形参重新指向新对象不会影响外部变量。这一点常被误称为「按引用传递」。

```js
function setName(obj) {
  obj.name = "Mimas";
  obj = { name: "Other" };
  // ...
}

const person = {};
setName(person);
console.log(person.name); // "Mimas"
```

#### 1.4 确定类型

`typeof` 能准确区分原始类型，但对 `null` 返回 `"object"`，对数组和普通对象都返回 `"object"`。对象的具体类型用 `instanceof` 或 `Object.prototype.toString.call`，跨 iframe、跨 realm 时 `instanceof` 依赖的原型链不同源，应改用 `Array.isArray` 这类内置判定。

```js
typeof "a"; // "string"
typeof null; // "object"
[] instanceof Array; // true
Object.prototype.toString.call([]); // "[object Array]"
```

### 2. 执行上下文与作用域

执行上下文是变量和函数可访问的数据环境，分为全局上下文、函数上下文和块级上下文。代码执行时上下文按调用关系入栈、出栈，栈顶上下文对应当前正在执行的代码。

#### 2.1 上下文的生命周期

每个上下文经历创建与执行两个阶段。创建阶段确定作用域链、创建变量对象并绑定 `this`；执行阶段逐行求值。函数上下文在每次调用时新建，返回后出栈，其局部变量随之失去引用。

```js
function outer() {
  const local = 1; // 创建阶段登记，执行阶段赋值
  return local;
}

outer(); // 调用时入栈，返回时出栈
```

#### 2.2 作用域链

标识符解析沿作用域链由内向外逐层查找，直到全局上下文。作用域链在函数创建时依据词法位置确定，与调用位置无关，因此 JavaScript 采用词法作用域。内层可以访问外层变量，外层无法访问内层变量。

```js
const globalVar = "g";

function outer() {
  const outerVar = "o";
  function inner() {
    console.log(globalVar, outerVar); // 沿链向上解析
  }
  inner();
}

outer();
```

#### 2.3 变量对象与活动对象

早期规范用变量对象（Variable Object）描述上下文中的声明集合，函数上下文的对象另称活动对象（Activation Object），由 `arguments` 初始化并包含形参。当前规范已改用环境记录（Environment Record），但 VO/AO 仍是解释提升、闭包和 `with` 行为时常用的模型。

```js
function f(a) {
  var b = 2;
  // 活动对象中包含 a、arguments、b
  return a + b;
}

f(1); // 3
```

### 3. 变量声明与提升

声明在代码执行前被处理，`var` 声明的标识符被提升到所在函数或全局作用域的顶部并初始化为 `undefined`，赋值语句留在原位。`let` 和 `const` 的标识符同样被登记，但在声明语句执行前处于未初始化状态，访问即抛错。

#### 3.1 var 的提升

提升只移动声明，不移动赋值。函数声明整体提升，可以在声明之前调用；`var` 的函数表达式只提升变量名，调用发生在赋值之前会得到 `TypeError`。同一作用域内重复声明 `var` 不报错，后者覆盖前者的赋值。

```js
console.log(a); // undefined
var a = 1;

// sayHi(); // 可以调用，函数声明整体提升
function sayHi() {
  return "hi";
}

// sayBye(); // TypeError: sayBye is not a function
var sayBye = function () {
  return "bye";
};
```

#### 3.2 let、const 与暂时性死区

`let` 和 `const` 具有块级作用域，同一作用域内重复声明抛 `SyntaxError`。从块开始到声明语句执行之间的区域称为暂时性死区（TDZ），在此期间访问变量抛 `ReferenceError`，`typeof` 也不例外。`const` 要求声明时初始化，且绑定不可重新赋值。

```js
{
  // console.log(b); // ReferenceError: Cannot access 'b' before initialization
  let b = 1;
  const c = 2;
  // c = 3; // TypeError: Assignment to constant variable.
}
```

循环中的差异最能体现块级作用域的价值：`var` 只有一个共享绑定，回调读取到循环结束后的值；`let` 每次迭代创建新绑定，回调捕获各自的值。

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i)); // 3 3 3
}

for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log(j)); // 0 1 2
}
```

### 4. 垃圾回收

JavaScript 使用自动内存管理，引擎周期性找出不再可达的对象并释放其内存。判定依据是可到达性，而非变量是否被显式清空。回收过程会占用主线程时间片，因此对象的创建频率直接影响运行时的流畅度。

#### 4.1 标记清理

标记清理（mark-and-sweep）从根集合出发，根包括全局对象、当前调用栈中的局部变量和闭包引用，凡能被遍历到的对象打上标记，未被标记的对象被回收。V8 在此之上做分代：新生代对象存活率低，用 Scavenge 复制算法；老生代用标记整理，并配合增量标记与并发标记减少停顿。

```js
function createTemp() {
  const data = new Array(1e5).fill(0); // 函数返回后不可达
  return data.length;
}

createTemp(); // data 在返回后可被回收
```

#### 4.2 引用计数与循环引用

引用计数在对象的引用数归零时立即回收，实现简单但无法处理循环引用：两个对象互相持有对方，计数始终不为零，即使外部已无法访问。早期 IE 中 DOM 对象与 JS 对象的循环引用是典型的泄漏来源，现代引擎已统一采用标记清理，循环引用只要整体不可达就能被回收。

```js
function cycle() {
  const a = {};
  const b = {};
  a.ref = b;
  b.ref = a;
  // 函数返回后整体不可达，标记清理仍可回收
}

cycle();
```

#### 4.3 性能影响

频繁创建短命对象会提高新生代回收的频率，单次停顿虽短，累计仍会挤压渲染时间。长生命周期的对象会被晋升到老生代，老生代回收的停顿更长。优化方向是减少不必要的临时对象、复用缓冲区、避免在热路径上产生大量闭包和字符串拼接。

```js
// 热路径中反复创建大数组会放大 GC 压力
function render(items) {
  return items.map((item) => ({ ...item, selected: false }));
}
```

### 5. 内存管理

自动回收不等于无需管理。占用内存的根源是仍然可达的引用：全局变量、未解绑的监听、未清除的定时器、闭包捕获的大对象都会让本该释放的数据长期存活。常用手段是缩小引用范围，并在确定不再使用时主动断开引用。

#### 5.1 解除引用

对不再需要的全局变量或缓存置 `null`，可以让对象变为不可达。局部变量在函数返回后自然失效，不需要手动清理；真正需要处理的是跨调用存活的引用，例如模块级缓存。

```js
let cache = { data: new Array(1e5).fill(0) };

// 使用完毕
cache = null;
```

#### 5.2 隐藏类与属性形状

V8 为结构相同的对象复用隐藏类（hidden class），属性访问点据此做内联缓存。构造后动态增删属性、属性添加顺序不一致、使用 `delete` 都会导致隐藏类迁移，使属性访问退化为字典查找。稳定做法是在构造函数中一次性声明全部属性，避免运行期改变对象形状。

```js
function Point(x, y) {
  this.x = x; // 固定的属性添加顺序
  this.y = y;
}

const p = new Point(1, 2);
// delete p.x; // 破坏隐藏类，避免在热路径上使用
```

#### 5.3 常见泄漏场景

- 定时器与轮询未清除：`setInterval` 的回调持续持有外部变量，组件卸载后仍存活。
- 事件监听未移除：绑定的回调捕获了大对象或 DOM 节点。
- 闭包长期持有：返回的函数引用外层大数组或节点。
- 全局变量挂载：意外赋值或调试代码把数据写到 `window`。
- 已移除节点仍有引用：DOM 节点从文档中删除，但 JS 变量仍指向它，节点及其子树无法回收。

```js
const panel = document.getElementById("panel");

panel.remove(); // 从文档移除
// panel 仍被变量引用，节点无法回收
// 修正：把引用改为 let 并置为 null
```
