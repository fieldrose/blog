## 类型进阶

### 类型之间的关系

TypeScript 的类型检查最终落在可赋值性上，而可赋值性由类型之间的父子关系决定。类、接口、数组、函数和泛型在参与比较时，父子关系的传递方式并不相同，这部分由型变规则描述。

#### 子类型与超类型

> [!note]
>
> - 子类型：给定两个类型 A 和 B，若 B 是 A 的子类型（`B <: A`），那么在任何需要 A 的地方都可以使用 B（里氏替换原则，LSP）。
> - 超类型：A 是 B 的超类型（`A >: B`），方向与子类型相反，在任何需要 B 的地方都可以使用 A。

子类型关系并不要求显式继承。在结构化类型系统下，只要一个类型提供的成员覆盖了另一个类型的要求，两者就构成子类型关系。可赋值性的方向始终是「子类型 → 超类型」。

```ts
interface Animal {
  name: string;
}
interface Dog extends Animal {
  bark(): void;
}

declare const dog: Dog;
const animal: Animal = dog; // ✓ Dog 是 Animal 的子类型
// const back: Dog = animal; // ✗ 超类型不能赋给子类型
```

#### 型变

泛型和复合类型在类型参数外再包一层结构，包装之后是否保留原有的父子关系，由型变（Variance）决定。设 `B <: A`：

- 若 `F<B>` 可以赋给 `F<A>`，说明子类型方向被保留，称为协变。
- 若 `F<A>` 可以赋给 `F<B>`，说明子类型方向被反转，称为逆变。
- 若两个方向都可赋值，称为双变。
- 若只有 `A` 与 `B` 完全相同时才可赋值，称为不变。

对常见复合类型，判断规则可以归纳为三条：

- 数组：`T` 是 `U` 的子类型时，`Array<T>` 可以赋给 `Array<U>`，即数组在 TypeScript 中是协变的。
- 结构：B 要求的属性在 A 中都存在，且 A 的对应属性类型是 B 的子类型时，A 是 B 的子类型。
- 函数：`(a: A) => B` 是 `(c: C) => D` 的子类型，当且仅当 `C` 是 `A` 的子类型（参数逆变），且 `B` 是 `D` 的子类型（返回值协变）。

在复杂类型的判断上，各语言之间存在差异，甚至同一门语言的不同声明形式也会给出不同结果。

##### 协变

协变保留子类型方向，常见于只读位置：函数返回值、`readonly` 属性、只读数组。调用方只读取数据时，把更具体的类型当作更宽泛的类型使用是安全的。

```ts
// 返回值是协变的
type GetAnimal = () => Animal;
type GetDog = () => Dog;

const getDog: GetDog = () => ({ name: "jack", bark: () => {} });
const getAnimal: GetAnimal = getDog; // ✓ 调用方只依赖返回值的 Animal 部分
```

数组同样按协变处理，读取位置因此安全，但数组同时支持写入，协变会在写入位置留下漏洞：

```ts
const dogs: Dog[] = [{ name: "jack", bark: () => {} }];
const animals: Animal[] = dogs; // ✓ 编译通过

animals.push({ name: "tom" }); // ✓ 编译通过，但写入的是普通 Animal
dogs[1].bark(); // 运行时 dogs[1] 没有 bark，报错
```

> [!note]
> 数组协变是 TypeScript 为兼容存量 JS 代码保留的行为：读取安全，写入不安全。需要明确只读语义时使用 `readonly T[]`；需要同时读写时，不应把子类型数组当作超类型数组使用。

##### 逆变

逆变反转子类型方向，典型位置是函数参数。能处理 Animal 的函数，自然也能处理它的子类型 Dog；反过来则不成立。

```ts
type AnimalHandler = (a: Animal) => void;
type DogHandler = (a: Dog) => void;

const animalHandler: AnimalHandler = a => {
  console.log(a.name);
};
const dogHandler: DogHandler = animalHandler; // ✓ 能处理 Animal 的函数，自然也能处理 Dog

// animalHandler = dogHandler; // ✗ 若允许，传入普通 Animal 时 a.bark() 会崩溃
```

参数位置按逆变检查由 `strictFunctionTypes` 控制，开启 `strict: true` 后默认生效。

##### 双变

方法简写形式（`handle(a: Animal): void`）的参数位置默认双变，即使开启 `strictFunctionTypes` 也不会拦截：

```ts
interface AnimalHandler {
  handle(a: Animal): void;
}
interface DogHandler {
  handle(a: Dog): void;
}

declare const animalHandler: AnimalHandler;
declare const dogHandler: DogHandler;

const a1: DogHandler = animalHandler; // ✓
const a2: AnimalHandler = dogHandler; // ✓ 方法参数双变，两个方向都放行
```

这是 TypeScript 早期为兼容 DOM 事件回调等存量写法留下的行为，类型上并不安全。把方法改写为属性形式的函数类型后，参数才会按逆变检查：

```ts
interface AnimalHandler {
  handle: (a: Animal) => void;
}
interface DogHandler {
  handle: (a: Dog) => void;
}

declare const animalHandler: AnimalHandler;
declare const dogHandler: DogHandler;

const a1: DogHandler = animalHandler; // ✓
// const a2: AnimalHandler = dogHandler; // ✗ strictFunctionTypes 下按逆变检查
```

##### 不变

读写都要求类型完全一致时，泛型应表现为不变。TypeScript 不会因为泛型类同时包含读取和写入操作就自动判定为不变：方法参数是双变的，`Box<Dog>` 仍然可以赋给 `Box<Animal>`。

```ts
class Box<T> {
  private value!: T;

  setValue(val: T) {
    this.value = val;
  }

  getValue(): T {
    return this.value;
  }
}

declare const dogBox: Box<Dog>;
const animalBox: Box<Animal> = dogBox; // ✓ 方法参数双变，TS 放行
animalBox.setValue({ name: "tom" }); // 编译通过，运行时把普通 Animal 写进了 Dog 实例
```

把读写成员改写为属性形式的函数类型，`strictFunctionTypes` 才会按逆变检查，两个方向都不再兼容：

```ts
class StrictBox<T> {
  private value!: T;

  setValue: (val: T) => void = val => {
    this.value = val;
  };

  getValue = (): T => this.value;
}

declare const dogBox: StrictBox<Dog>;
// const animalBox: StrictBox<Animal> = dogBox; // ✗ 属性函数按逆变检查
```

##### 小结

| 型变 | 可赋值方向      | TypeScript 中的典型位置                | 类型安全性           |
| ---- | --------------- | -------------------------------------- | -------------------- |
| 协变 | `F<B>` → `F<A>` | 函数返回值、只读数组、`readonly` 属性  | 安全                 |
| 逆变 | `F<A>` → `F<B>` | `strictFunctionTypes` 下的函数类型参数 | 安全                 |
| 双变 | 双向均可        | 方法简写形式的参数                     | 不安全，属兼容性妥协 |
| 不变 | 仅同型          | 属性形式的读写函数类型组合             | 安全，需显式构造     |

型变不是由泛型名决定的固定属性，而取决于类型参数出现的位置：只读位置协变，写入位置逆变，方法简写形式则放宽为双变。判断可赋值性时，应以实际声明形式为准。

#### 可赋值性

对于A，B两个类型，满足下列两个条件中的任意一个，即可认为A可以赋值给B：

1. A<:B A是B的子类型
2. A是any any是所有类型的子类型

对于enum类型和const enum类型

1. A是枚举B的成员
2. B中至少有一个成员是number类型，且A是数字 这点也导致了类型安全隐患

#### 类型拓宽

ts在推导类型时会倾向于选择更宽泛的类型，而不是更窄的类型。

```ts
// 使用var或let声明的变量会在自动推导时拓宽类型
var a = true; // boolean
let b = 3; // number

const c = "123"; // '123'
// 显式注解也可以避免类型拓宽
let d: "x" = "x"; // 'x'
// 重复的声明也会导致类型拓宽
let e = c; // string

// null和undefined会被拓宽为any
let f = null; // any
let g = undefined; // any
```

初始化为null和undefined的变量在离开声明作用域后，会被分配一个类型

```ts
function bar() {
  let a = null; // any
  a = 1; // any
  a = "123"; // any
  return a;
}
bar(); // string
```

##### 特殊类型const

在单个声明中禁用类型拓宽,可以结合类型断言使用

```ts
let a = { x: 1 }; // {x:number}
let b = { x: 1 } as const; // {readonly x:1}

// const可以递归深度限制类型
let c = { x: { y: 1 } }; // {x:{y:number}}
let d = { x: { y: 1 } } as const; // {readonly x:{readonly y:1}}
```
