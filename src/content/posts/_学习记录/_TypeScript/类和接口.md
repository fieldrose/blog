## 类和接口

ts类大量借鉴了C#相关理论（同一个人设计的），且能兼容js的常规写法，如兼顾类型安全的混入（mixin）。

### 1. 类和继承

#### 1.1 类的声明与继承

类使用 `class` 关键字声明，子类使用 `extends` 继承父类。子类会继承父类的实例属性和方法，也可以新增或重写方法。

```ts
class Animal {
  move(): string {
    return "move";
  }
}

class Dog extends Animal {
  bark(): string {
    return "woof";
  }
}

const dog = new Dog();
console.log(dog.move(), dog.bark());
```

#### 1.2 具体类与抽象类

类可以是具体类，也可以是使用 `abstract` 声明的抽象类。抽象类不能直接实例化，通常作为子类的公共模板。

抽象类可以包含抽象属性、抽象方法和已实现的方法。抽象成员只声明结构、不提供实现，由子类负责实现。

```ts
abstract class Animal {
  abstract name: string;
  abstract speak(): string;

  move(): string {
    return "move";
  }
}

class Dog extends Animal {
  // 抽象类中用`abstract` 声明的实例属性和实例方法，必须由最终的非抽象子类实现；已经提供实现的普通成员无需重写。
  // 若有多层抽象子类，抽象子类可以提前实现一部分，也可以都不实现
  // 若有多层非抽象子类，则第一个非抽象子类必须实现所有抽象属性和方法
  name = "dog";
  speak(): string {
    return "woof";
  }
  // 其余属性和方法如静态和实例，可以在子类中直接使用
}

const dog = new Dog();
console.log(dog.name, dog.speak(), dog.move());
```

#### 1.3 方法分类与可见性

方法分为实例方法和静态方法：实例方法通过实例调用；静态方法使用 `static` 声明，通过类名调用，无需创建实例。

方法与属性的可见性修饰符默认是 `public`，三者的访问范围如下：

- `public`：类内部、子类和类外部均可访问。
- `protected`：类内部和子类可访问，类外部不可访问。
- `private`：仅声明该成员的类内部可访问，子类也不能直接访问。

```ts
class Animal {
  public name = "animal";
  protected age = 1;
  private id = 0;

  static create(): Animal {
    return new Animal();
  }

  move(): string {
    return `${this.id}: move`;
  }
}

class Dog extends Animal {
  getAge(): number {
    return this.age;
  }
}

const dog = new Dog();
dog.move();
Animal.create();
```

#### 1.4 实例属性的声明

实例属性可以直接在类体中声明并初始化，也可以通过构造函数的参数属性声明，可见性同样支持 `public`、`protected` 和 `private`。

其中，`constructor(public id: number) {}` 是 **参数属性（parameter property）** 的简写，同时完成三项操作：

1. 声明实例属性 `id`。
2. 将属性可见性设为 `public`。
3. 自动把构造函数参数赋值给 `this.id`，因此构造函数体可以为空。

`public` 也可以替换为 `protected` 或 `private`，还可以使用 `readonly` 限制属性重新赋值。如果未添加上述任一修饰符，`id` 就只是普通的构造函数参数，不会生成实例属性。

```ts
class User {
  name = "anonymous";

  // [!code --:4]
  id: number;
  constructor(id: number) {
    this.id = id;
  }
  // [!code ++:1]
  constructor(public id: number) {}
}

const user = new User(1);
console.log(user.id, user.name);
```

#### 1.5 readonly 属性

实例属性可以使用 `readonly` 声明，表示属性初始化后不能重新赋值。它只限制属性的写入，不影响读取，属性的访问范围仍由 `public`、`protected` 和 `private` 决定。

`readonly` 属性有两个初始化位置：

1. 在属性声明时直接初始化。
2. 在所属类的构造函数中赋值。

```ts
class User {
  readonly createdAt = new Date();
  readonly id: number;

  constructor(id: number) {
    this.id = id;
  }

  update(): void {
    // this.id = 2; // Error: cannot assign to a readonly property
  }
}

const user = new User(1);
console.log(user.id);
// user.id = 2; // Error: cannot assign to a readonly property
```

`readonly` 也可以用于参数属性。下面的写法会声明一个公开的只读实例属性（默认可见性为 `public`，可与可见性修饰符 `public`、`protected` 或 `private` 组合使用），并自动完成初始化：

```ts
class User {
  constructor(public readonly id: number) {}
}
```

`readonly` 只禁止给属性本身重新赋值，不会递归地将属性值变为只读。属性值是对象或数组时，其内部成员仍可修改：

```ts
class User {
  readonly profile = { name: "Mimas" };
}

const user = new User();
// user.profile = { name: "Other" }; // Error: cannot reassign the property
user.profile.name = "Other"; // 允许修改
```

此外，`readonly` 是 TS 的编译期约束，不会自动冻结对象；编译成 JS 后，该修饰符不会保留在运行时代码中。

##### 补充

```ts
// DeepReadonly<T>：递归地将 T 中每一层对象的属性都转换为 readonly。
// T 表示当前正在处理的类型，既可能是最外层的对象，也可能是某个嵌套属性的值类型。
type DeepReadonly<T> = T extends Function
  ? // 函数在 TS 中也属于 object，因此必须先判断函数，再判断普通对象。
    // 如果函数进入下面的对象映射分支，就会被转换成普通对象类型，丢失原有的调用签名。
    // 这里直接返回 T，保留函数原有的参数、返回值和调用能力，不为函数添加只读转换。
    T
  : T extends object
    ? {
        // keyof T 获取当前对象所有键组成的联合类型，P 表示本次遍历到的键。
        // readonly 为当前层的每个属性添加只读限制，禁止重新给这些属性赋值。
        // T[P] 是属性 P 对应的值类型，例如 User["profile"] 就是 profile 属性的类型。
        // DeepReadonly<T[P]> 对属性值继续执行相同判断：如果值仍是对象，就继续处理下一层。
        // 因此，readonly 负责当前层，递归调用负责嵌套层，两者组合后形成深层只读。
        readonly [P in keyof T]: DeepReadonly<T[P]>;
      }
    : // string、number、boolean、null、undefined 等非对象类型没有可映射的属性，直接返回原类型。
      // 递归处理到这些基础类型时，也会在这里结束，不会无限向下展开。
      T;

// 该工具类型只影响编译期的类型检查，不会修改或冻结运行时对象。
```

### 2. super

TS 沿用 JS 的 `super` 语法。在类继承中，`super` 主要有两种用途：在子类构造函数中调用父类构造函数，以及在子类方法中访问父类的方法。

`extends` 负责建立类之间的继承关系，`super` 则用于复用父类的初始化逻辑或方法实现。

#### 2.1 调用父类构造函数

子类声明了自己的构造函数时，需要通过 `super(...args)` 调用父类构造函数，并且必须在访问 `this` 之前完成调用。父类完成其负责部分的初始化后，子类才能继续使用当前实例。

```ts
class Animal {
  constructor(public name: string) {}
}

class Dog extends Animal {
  constructor(name: string) {
    super(name);

    // 必须在 super() 之后才能访问 this
    console.log(this.name);
  }
}

const dog = new Dog("Buddy");
```

如果子类没有声明构造函数，会自动将接收到的参数转发给父类构造函数，无需显式补写 `constructor` 和 `super()`。

#### 2.2 调用父类方法

子类重写父类方法后，可以使用 `super.method()` 调用父类的对应方法，再补充子类自己的逻辑，避免重复父类已有的实现。调用父类方法时，方法内部的 `this` 仍然指向当前子类实例。

```ts
class Animal {
  constructor(public name: string) {}

  speak(): string {
    return `${this.name}: ...`;
  }
}

class Dog extends Animal {
  speak(): string {
    return `${super.speak()} woof`;
  }
}

const dog = new Dog("Buddy");
console.log(dog.speak()); // Buddy: ... woof
```

在静态方法中也可以使用 `super.method()`，此时调用的是父类的静态方法。

#### 2.3 super 与实例属性

`super` 不是父类实例的引用，`super` 本身也不能作为普通值使用，只能采用 `super(...)` 或 `super.property` 的形式。实例方法中的 `super.method()` 主要用于查找父类原型上的方法。

父类通过构造函数或实例字段初始化语法创建的属性，直接保存在当前实例上，应通过 `this.name` 访问，而不是 `super.name`：

```ts
// 沿用上文的 Animal 定义
class Dog extends Animal {
  printName(): void {
    console.log(this.name);
  }
}
```

### 3. 以 this 为返回类型

在类或接口中，可以将 `this` 用作方法的返回类型，称为**多态 `this` 类型（polymorphic `this` type）**。它表示当前实例的类型，并能在继承场景中保留子类类型，最常见的用途是实现链式调用。

#### 3.1 基本链式调用

方法在末尾执行 `return this`，会将当前实例作为调用结果返回，因此可以继续调用该实例的其他方法。链式调用操作的是同一个对象，不会在每次调用时自动创建新实例。

```ts
class NumberSet {
  private values = new Set<number>();

  has(value: number): boolean {
    return this.values.has(value);
  }

  add(value: number): this {
    this.values.add(value);
    return this;
  }
}

const numbers = new NumberSet().add(1).add(2);

console.log(numbers.has(1)); // true
console.log(numbers.has(3)); // false
```

#### 3.2 继承时保留子类类型

如果父类方法的返回类型写成父类名，子类实例调用该方法后，表达式会被视为父类类型，无法继续调用仅存在于子类的方法。将返回类型改为 `this` 后，TS 会保留调用处的子类类型。

```ts
class Counter {
  count = 0;

  increment(): this {
    this.count += 1;
    return this;
  }
}

class ResettableCounter extends Counter {
  reset(): this {
    this.count = 0;
    return this;
  }
}

const counter = new ResettableCounter().increment().reset().increment();

console.log(counter.count); // 1
```

上例中，`increment()` 虽然声明在 `Counter` 上，但通过 `ResettableCounter` 实例调用后，返回类型仍是 `ResettableCounter`，因此可以继续调用 `reset()`。

如果把 `increment()` 的返回类型改为 `Counter`，调用到 `increment()` 后，静态类型就会退化为 `Counter`，后续调用 `reset()` 会因 `Counter` 未声明该方法而报错。

#### 3.3 使用边界

`this` 返回类型适用于返回当前实例的方法，但并非所有方法都应该链式化：

- 修改状态或配置的方法可以返回 `this`，形成流式调用接口。
- 查询或计算方法应返回实际结果，例如 `has(): boolean`，不需要返回 `this`。
- 如果方法内部创建并返回新对象，应使用新对象的实际返回类型，不能为了链式调用而返回当前实例。

运行时的 `return this` 只是返回当前对象的引用；类型层的 `this` 则负责在编译期保留当前类或子类的类型关系。

### 4. 接口

接口用于描述值应具备的结构，只参与编译期类型检查，不会生成 JS 代码。通过 `interface` 可以声明属性、方法以及可选成员：

```ts
interface User {
  readonly id: number;
  name: string;
  age?: number;
}

const user: User = {
  id: 1,
  name: "Mimas",
};
```

其中，`readonly` 禁止重新给属性赋值，`?` 表示属性可以省略。接口描述对象结构时与类型别名相近，但两者的适用范围不同：

- 类型别名可以表示基础类型、联合类型、交叉类型和元组等任意类型。
- 接口主要用于描述对象、函数等结构，支持 `extends` 和声明合并。

```ts
type ID = number | string;
type UserWithAge = User & { age: number };

interface NamedUser extends User {
  nickname: string;
}
```

接口可以扩展一个或多个接口，也可以扩展对象类型或类。扩展包含 `private` 或 `protected` 成员的类时，只有该类及其子类才能满足这个接口。

#### 4.1 声明合并

同一作用域内，多个同名接口会自动合并，最终使用时需要同时满足所有声明：

```ts
interface User {
  id: number;
}

interface User {
  name: string;
}

const user: User = {
  id: 1,
  name: "Mimas",
};
```

合并时，同名属性必须保持类型一致，否则会产生类型错误：

```ts
interface User {
  id: number;
}

interface User {
  id: string; // Error: 与已有 id: number 冲突
}
```

泛型接口也可以合并，但各声明的泛型参数列表必须一致，包括参数名称和约束：

```ts
interface User<Age extends number> {
  age: Age;
}

interface User<Age extends number> {
  nickname: string;
}
```

类型别名不支持声明合并，同一作用域内重复声明同名 `type` 会直接报错。另外，包含顶层 `import` 或 `export` 的文件属于模块，其中的接口不会自动与其他模块中的同名接口合并。

#### 4.2 实现

类通过 `implements` 声明自己满足某个接口。TS 会检查类是否提供接口要求的全部必需成员，但接口本身不提供任何实现：

```ts
interface Animal {
  eat(food: string): void;
}

class Dog implements Animal {
  eat(food: string): void {
    console.log(`I eat ${food}`);
  }
}
```

一个类可以同时实现多个接口。接口中的 `readonly` 属性可以由构造函数初始化，但初始化后不能重新赋值：

```ts
interface Animal {
  eat(food: string): void;
}

interface Named {
  readonly name: string;
}

class Dog implements Animal, Named {
  readonly name: string;

  constructor(name: string) {
    this.name = name;
  }

  eat(food: string): void {
    console.log(`I eat ${food}`);
  }
}
```

接口描述的是实例侧的公共结构，不能声明 `public`、`protected`、`private` 等可见性修饰符，也不能声明静态属性或静态方法。类可以拥有接口之外的额外成员，但不能缺少接口要求的必需成员。

#### 4.3 实现接口还是抽象类

接口和抽象类都能约束子类或实现类，但职责不同：

- 只需要描述结构、统一不同类的公共能力时，使用接口。接口不生成运行时代码，一个类可以实现多个接口。
- 需要共享状态、构造函数或方法的公共实现时，使用抽象类。抽象类会生成运行时代码，支持可见性修饰符，但类只能单继承。

两者也可以组合：抽象类提供公共实现，接口声明对外能力。

```ts
interface Printable {
  print(): string;
}

abstract class Document {
  protected abstract title: string;

  print(): string {
    return `Printing ${this.title}`;
  }
}

class Report extends Document implements Printable {
  protected title = "Report";
}
```

`Report` 从 `Document` 继承 `print()` 的实现，同时通过 `implements Printable` 声明自己满足接口结构。接口负责描述能力，抽象类负责复用实现。

### 5. 类是结构化类型

TS 使用结构化类型系统判断兼容性：类实例是否可赋值给某个类型，主要取决于它是否提供该类型要求的成员，而不是类名、继承声明或 `implements` 声明。

#### 5.1 公开成员按结构比较

两个类即使没有继承关系，只要实例的公开成员兼容，就可以相互赋值：

```ts
class A {
  constructor(public name: string) {}
}

class B {
  constructor(public name: string) {}
}

function printName(instance: A): void {
  console.log(instance.name);
}

printName(new A("Mimas"));
printName(new B("Mimas")); // B 的公开结构满足 A
```

普通对象同样可以满足类的实例类型，不要求必须通过 `new A()` 创建：

```ts
const instance: A = {
  name: "Mimas",
};

printName(instance);
```

结构兼容并不要求双方成员完全相同，而是要求源类型至少提供目标类型要求的成员，且对应成员的类型兼容。源类型可以拥有额外成员。

这里比较的是类的**实例类型**，构造函数和静态成员不参与上述实例兼容性检查。

#### 5.2 private 与 protected 的限制

目标类包含 `private` 或 `protected` 成员时，兼容性还受成员声明来源限制。即使另一个类或对象具有同名、同类型成员，也不能仅靠结构满足目标类型：

```ts
class A {
  private x = 1;
}

class B extends A {}

class C {
  private x = 1;
}

function f(a: A): void {}

f(new A());
f(new B()); // x 继承自 A，声明来源相同
f(new C()); // Error: C.x 与 A.x 来自不同的 private 声明
f({ x: 1 }); // Error: 普通对象不具备 A 的 private 成员
```

`B` 继承了 `A` 的私有成员，因此 `B` 实例可以赋值给 `A`；`C` 虽然写出了相同的属性结构，但其 `x` 来自另一份 `private` 声明，仍然不兼容。`protected` 成员也遵循相同的声明来源限制。

因此，包含 `private` 或 `protected` 成员的类不再只是单纯按公开结构比较，而是带有一定的名义类型约束。

### 8. 混入

```ts
type Constructor<T = object> = new (...args: any[]) => T;

function WithTimestamp<TBase extends Constructor>(Base: TBase) {
  return class extends Base {
    createdAt = new Date();
  };
}

class User {}
const TimestampedUser = WithTimestamp(User);
const user = new TimestampedUser();

console.log(user.createdAt);
```

### 11. 设计模式

#### 11.1 工厂模式

```ts
interface Shape {
  draw(): string;
}

class Circle implements Shape {
  draw(): string {
    return "circle";
  }
}

class Square implements Shape {
  draw(): string {
    return "square";
  }
}

function createShape(type: "circle" | "square"): Shape {
  return type === "circle" ? new Circle() : new Square();
}

const shape = createShape("circle");
```

#### 11.2 建造者模式

```ts
class QueryBuilder {
  private table = "";
  private condition = "";

  from(table: string): this {
    this.table = table;
    return this;
  }

  where(condition: string): this {
    this.condition = condition;
    return this;
  }

  build(): string {
    return `SELECT * FROM ${this.table} WHERE ${this.condition}`;
  }
}

const query = new QueryBuilder().from("users").where("active = true").build();
```
