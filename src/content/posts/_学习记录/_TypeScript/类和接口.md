## Table of contents

## 类和接口

ts类大量借鉴了C#相关理论（同一个人设计的），且能兼容js的常规写法，如兼顾类型安全的混入（mixin）。

### 1. 类和继承

#### 1.1 类的声明与继承

类使用 `class` 关键字声明，子类使用 `extends` 继承父类。子类会继承父类的实例属性和方法，也可以新增或重写方法。

```ts
class Animal {
  move(): string {
    return "move";
  }
}

class Dog extends Animal {
  bark(): string {
    return "woof";
  }
}

const dog = new Dog();
console.log(dog.move(), dog.bark());
```

#### 1.2 具体类与抽象类

类可以是具体类，也可以是使用 `abstract` 声明的抽象类。抽象类不能直接实例化，通常作为子类的公共模板。

抽象类可以包含抽象属性、抽象方法和已实现的方法。抽象成员只声明结构、不提供实现，由子类负责实现。

```ts
abstract class Animal {
  abstract name: string;
  abstract speak(): string;

  move(): string {
    return "move";
  }
}

class Dog extends Animal {
  // 抽象类中用`abstract` 声明的实例属性和实例方法，必须由最终的非抽象子类实现；已经提供实现的普通成员无需重写。
  // 若有多层抽象子类，抽象子类可以提前实现一部分，也可以都不实现
  // 若有多层非抽象子类，则第一个非抽象子类必须实现所有抽象属性和方法
  name = "dog";
  speak(): string {
    return "woof";
  }
  // 其余属性和方法如静态和实例，可以在子类中直接使用
}

const dog = new Dog();
console.log(dog.name, dog.speak(), dog.move());
```

#### 1.3 方法分类与可见性

方法分为实例方法和静态方法：实例方法通过实例调用；静态方法使用 `static` 声明，通过类名调用，无需创建实例。

方法与属性的可见性修饰符默认是 `public`，三者的访问范围如下：

- `public`：类内部、子类和类外部均可访问。
- `protected`：类内部和子类可访问，类外部不可访问。
- `private`：仅声明该成员的类内部可访问，子类也不能直接访问。

```ts
class Animal {
  public name = "animal";
  protected age = 1;
  private id = 0;

  static create(): Animal {
    return new Animal();
  }

  move(): string {
    return `${this.id}: move`;
  }
}

class Dog extends Animal {
  getAge(): number {
    return this.age;
  }
}

const dog = new Dog();
dog.move();
Animal.create();
```

#### 1.4 实例属性的声明

实例属性可以直接在类体中声明并初始化，也可以通过构造函数的参数属性声明，可见性同样支持 `public`、`protected` 和 `private`。

其中，`constructor(public id: number) {}` 是 **参数属性（parameter property）** 的简写，同时完成三项操作：

1. 声明实例属性 `id`。
2. 将属性可见性设为 `public`。
3. 自动把构造函数参数赋值给 `this.id`，因此构造函数体可以为空。

`public` 也可以替换为 `protected` 或 `private`，还可以使用 `readonly` 限制属性重新赋值。如果未添加上述任一修饰符，`id` 就只是普通的构造函数参数，不会生成实例属性。

```ts
class User {
  name = "anonymous";

  // [!code --:4]
  id: number;
  constructor(id: number) {
    this.id = id;
  }
  // [!code ++:1]
  constructor(public id: number) {}
}

const user = new User(1);
console.log(user.id, user.name);
```

#### 1.5 readonly 属性

实例属性可以使用 `readonly` 声明，表示属性初始化后不能重新赋值。它只限制属性的写入，不影响读取，属性的访问范围仍由 `public`、`protected` 和 `private` 决定。

`readonly` 属性有两个初始化位置：

1. 在属性声明时直接初始化。
2. 在所属类的构造函数中赋值。

```ts
class User {
  readonly createdAt = new Date();
  readonly id: number;

  constructor(id: number) {
    this.id = id;
  }

  update(): void {
    // this.id = 2; // Error: cannot assign to a readonly property
  }
}

const user = new User(1);
console.log(user.id);
// user.id = 2; // Error: cannot assign to a readonly property
```

`readonly` 也可以用于参数属性。下面的写法会声明一个公开的只读实例属性（默认可见性为 `public`，可与可见性修饰符 `public`、`protected` 或 `private` 组合使用），并自动完成初始化：

```ts
class User {
  constructor(public readonly id: number) {}
}
```

`readonly` 只禁止给属性本身重新赋值，不会递归地将属性值变为只读。属性值是对象或数组时，其内部成员仍可修改：

```ts
class User {
  readonly profile = { name: "Mimas" };
}

const user = new User();
// user.profile = { name: "Other" }; // Error: cannot reassign the property
user.profile.name = "Other"; // 允许修改
```

此外，`readonly` 是 TS 的编译期约束，不会自动冻结对象；编译成 JS 后，该修饰符不会保留在运行时代码中。

##### 补充

```ts
// DeepReadonly<T>：递归地将 T 中每一层对象的属性都转换为 readonly。
// T 表示当前正在处理的类型，既可能是最外层的对象，也可能是某个嵌套属性的值类型。
type DeepReadonly<T> = T extends Function
  ? // 函数在 TS 中也属于 object，因此必须先判断函数，再判断普通对象。
    // 如果函数进入下面的对象映射分支，就会被转换成普通对象类型，丢失原有的调用签名。
    // 这里直接返回 T，保留函数原有的参数、返回值和调用能力，不为函数添加只读转换。
    T
  : T extends object
    ? {
        // keyof T 获取当前对象所有键组成的联合类型，P 表示本次遍历到的键。
        // readonly 为当前层的每个属性添加只读限制，禁止重新给这些属性赋值。
        // T[P] 是属性 P 对应的值类型，例如 User["profile"] 就是 profile 属性的类型。
        // DeepReadonly<T[P]> 对属性值继续执行相同判断：如果值仍是对象，就继续处理下一层。
        // 因此，readonly 负责当前层，递归调用负责嵌套层，两者组合后形成深层只读。
        readonly [P in keyof T]: DeepReadonly<T[P]>;
      }
    : // string、number、boolean、null、undefined 等非对象类型没有可映射的属性，直接返回原类型。
      // 递归处理到这些基础类型时，也会在这里结束，不会无限向下展开。
      T;

// 该工具类型只影响编译期的类型检查，不会修改或冻结运行时对象。
```

### 2. super

TS 沿用 JS 的 `super` 语法。在类继承中，`super` 主要有两种用途：在子类构造函数中调用父类构造函数，以及在子类方法中访问父类的方法。

`extends` 负责建立类之间的继承关系，`super` 则用于复用父类的初始化逻辑或方法实现。

#### 2.1 调用父类构造函数

子类声明了自己的构造函数时，需要通过 `super(...args)` 调用父类构造函数，并且必须在访问 `this` 之前完成调用。父类完成其负责部分的初始化后，子类才能继续使用当前实例。

```ts
class Animal {
  constructor(public name: string) {}
}

class Dog extends Animal {
  constructor(name: string) {
    super(name);

    // 必须在 super() 之后才能访问 this
    console.log(this.name);
  }
}

const dog = new Dog("Buddy");
```

如果子类没有声明构造函数，会自动将接收到的参数转发给父类构造函数，无需显式补写 `constructor` 和 `super()`。

#### 2.2 调用父类方法

子类重写父类方法后，可以使用 `super.method()` 调用父类的对应方法，再补充子类自己的逻辑，避免重复父类已有的实现。调用父类方法时，方法内部的 `this` 仍然指向当前子类实例。

```ts
class Animal {
  constructor(public name: string) {}

  speak(): string {
    return `${this.name}: ...`;
  }
}

class Dog extends Animal {
  speak(): string {
    return `${super.speak()} woof`;
  }
}

const dog = new Dog("Buddy");
console.log(dog.speak()); // Buddy: ... woof
```

在静态方法中也可以使用 `super.method()`，此时调用的是父类的静态方法。

#### 2.3 super 与实例属性

`super` 不是父类实例的引用，`super` 本身也不能作为普通值使用，只能采用 `super(...)` 或 `super.property` 的形式。实例方法中的 `super.method()` 主要用于查找父类原型上的方法。

父类通过构造函数或实例字段初始化语法创建的属性，直接保存在当前实例上，应通过 `this.name` 访问，而不是 `super.name`：

```ts
// 沿用上文的 Animal 定义
class Dog extends Animal {
  printName(): void {
    console.log(this.name);
  }
}
```

### 3. 以 this 为返回类型

在类或接口中，可以将 `this` 用作方法的返回类型，称为**多态 `this` 类型（polymorphic `this` type）**。它表示当前实例的类型，并能在继承场景中保留子类类型，最常见的用途是实现链式调用。

#### 3.1 基本链式调用

方法在末尾执行 `return this`，会将当前实例作为调用结果返回，因此可以继续调用该实例的其他方法。链式调用操作的是同一个对象，不会在每次调用时自动创建新实例。

```ts
class NumberSet {
  private values = new Set<number>();

  has(value: number): boolean {
    return this.values.has(value);
  }

  add(value: number): this {
    this.values.add(value);
    return this;
  }
}

const numbers = new NumberSet().add(1).add(2);

console.log(numbers.has(1)); // true
console.log(numbers.has(3)); // false
```

#### 3.2 继承时保留子类类型

如果父类方法的返回类型写成父类名，子类实例调用该方法后，表达式会被视为父类类型，无法继续调用仅存在于子类的方法。将返回类型改为 `this` 后，TS 会保留调用处的子类类型。

```ts
class Counter {
  count = 0;

  increment(): this {
    this.count += 1;
    return this;
  }
}

class ResettableCounter extends Counter {
  reset(): this {
    this.count = 0;
    return this;
  }
}

const counter = new ResettableCounter().increment().reset().increment();

console.log(counter.count); // 1
```

上例中，`increment()` 虽然声明在 `Counter` 上，但通过 `ResettableCounter` 实例调用后，返回类型仍是 `ResettableCounter`，因此可以继续调用 `reset()`。

如果把 `increment()` 的返回类型改为 `Counter`，调用到 `increment()` 后，静态类型就会退化为 `Counter`，后续调用 `reset()` 会因 `Counter` 未声明该方法而报错。

#### 3.3 使用边界

`this` 返回类型适用于返回当前实例的方法，但并非所有方法都应该链式化：

- 修改状态或配置的方法可以返回 `this`，形成流式调用接口。
- 查询或计算方法应返回实际结果，例如 `has(): boolean`，不需要返回 `this`。
- 如果方法内部创建并返回新对象，应使用新对象的实际返回类型，不能为了链式调用而返回当前实例。

运行时的 `return this` 只是返回当前对象的引用；类型层的 `this` 则负责在编译期保留当前类或子类的类型关系。

### 4. 接口

接口用于描述值应具备的结构，只参与编译期类型检查，不会生成 JS 代码。通过 `interface` 可以声明属性、方法以及可选成员：

```ts
interface User {
  readonly id: number;
  name: string;
  age?: number;
}

const user: User = {
  id: 1,
  name: "Mimas",
};
```

其中，`readonly` 禁止重新给属性赋值，`?` 表示属性可以省略。接口描述对象结构时与类型别名相近，但两者的适用范围不同：

- 类型别名可以表示基础类型、联合类型、交叉类型和元组等任意类型。
- 接口主要用于描述对象、函数等结构，支持 `extends` 和声明合并。

```ts
type ID = number | string;
type UserWithAge = User & { age: number };

interface NamedUser extends User {
  nickname: string;
}
```

接口可以扩展一个或多个接口，也可以扩展对象类型或类。扩展包含 `private` 或 `protected` 成员的类时，只有该类及其子类才能满足这个接口。

#### 4.1 声明合并

同一作用域内，多个同名接口会自动合并，最终使用时需要同时满足所有声明：

```ts
interface User {
  id: number;
}

interface User {
  name: string;
}

const user: User = {
  id: 1,
  name: "Mimas",
};
```

合并时，同名属性必须保持类型一致，否则会产生类型错误：

```ts
interface User {
  id: number;
}

interface User {
  id: string; // Error: 与已有 id: number 冲突
}
```

泛型接口也可以合并，但各声明的泛型参数列表必须一致，包括参数名称和约束：

```ts
interface User<Age extends number> {
  age: Age;
}

interface User<Age extends number> {
  nickname: string;
}
```

类型别名不支持声明合并，同一作用域内重复声明同名 `type` 会直接报错。另外，包含顶层 `import` 或 `export` 的文件属于模块，其中的接口不会自动与其他模块中的同名接口合并。

#### 4.2 实现

类通过 `implements` 声明自己满足某个接口。TS 会检查类是否提供接口要求的全部必需成员，但接口本身不提供任何实现：

```ts
interface Animal {
  eat(food: string): void;
}

class Dog implements Animal {
  eat(food: string): void {
    console.log(`I eat ${food}`);
  }
}
```

一个类可以同时实现多个接口。接口中的 `readonly` 属性可以由构造函数初始化，但初始化后不能重新赋值：

```ts
interface Animal {
  eat(food: string): void;
}

interface Named {
  readonly name: string;
}

class Dog implements Animal, Named {
  readonly name: string;

  constructor(name: string) {
    this.name = name;
  }

  eat(food: string): void {
    console.log(`I eat ${food}`);
  }
}
```

接口描述的是实例侧的公共结构，不能声明 `public`、`protected`、`private` 等可见性修饰符，也不能声明静态属性或静态方法。类可以拥有接口之外的额外成员，但不能缺少接口要求的必需成员。

#### 4.3 实现接口还是抽象类

接口和抽象类都能约束子类或实现类，但职责不同：

- 只需要描述结构、统一不同类的公共能力时，使用接口。接口不生成运行时代码，一个类可以实现多个接口。
- 需要共享状态、构造函数或方法的公共实现时，使用抽象类。抽象类会生成运行时代码，支持可见性修饰符，但类只能单继承。

两者也可以组合：抽象类提供公共实现，接口声明对外能力。

```ts
interface Printable {
  print(): string;
}

abstract class Document {
  protected abstract title: string;

  print(): string {
    return `Printing ${this.title}`;
  }
}

class Report extends Document implements Printable {
  protected title = "Report";
}
```

`Report` 从 `Document` 继承 `print()` 的实现，同时通过 `implements Printable` 声明自己满足接口结构。接口负责描述能力，抽象类负责复用实现。

### 5. 类是结构化类型

TS 使用结构化类型系统判断兼容性：类实例是否可赋值给某个类型，主要取决于它是否提供该类型要求的成员，而不是类名、继承声明或 `implements` 声明。

#### 5.1 公开成员按结构比较

两个类即使没有继承关系，只要实例的公开成员兼容，就可以相互赋值：

```ts
class A {
  constructor(public name: string) {}
}

class B {
  constructor(public name: string) {}
}

function printName(instance: A): void {
  console.log(instance.name);
}

printName(new A("Mimas"));
printName(new B("Mimas")); // B 的公开结构满足 A
```

普通对象同样可以满足类的实例类型，不要求必须通过 `new A()` 创建：

```ts
const instance: A = {
  name: "Mimas",
};

printName(instance);
```

结构兼容并不要求双方成员完全相同，而是要求源类型至少提供目标类型要求的成员，且对应成员的类型兼容。源类型可以拥有额外成员。

这里比较的是类的**实例类型**，构造函数和静态成员不参与上述实例兼容性检查。

#### 5.2 private 与 protected 的限制

目标类包含 `private` 或 `protected` 成员时，兼容性还受成员声明来源限制。即使另一个类或对象具有同名、同类型成员，也不能仅靠结构满足目标类型：

```ts
class A {
  private x = 1;
}

class B extends A {}

class C {
  private x = 1;
}

function f(a: A): void {}

f(new A());
f(new B()); // x 继承自 A，声明来源相同
f(new C()); // Error: C.x 与 A.x 来自不同的 private 声明
f({ x: 1 }); // Error: 普通对象不具备 A 的 private 成员
```

`B` 继承了 `A` 的私有成员，因此 `B` 实例可以赋值给 `A`；`C` 虽然写出了相同的属性结构，但其 `x` 来自另一份 `private` 声明，仍然不兼容。`protected` 成员也遵循相同的声明来源限制。

因此，包含 `private` 或 `protected` 成员的类不再只是单纯按公开结构比较，而是带有一定的名义类型约束。

### 6. 类既是声明值也是声明类型

TypeScript 的标识符活在两个互不干扰的命名空间里：值空间存放运行时存在的实体，类型空间存放只在编译期生效的结构描述。绝大多数声明只落在一侧，类与枚举是少数同时落在两侧的例外。

#### 6.1 值空间与类型空间

```ts
// 值空间：变量、函数、类、枚举
let count = 1;
function format(input: string): string {
  return input.trim();
}

// 类型空间：type、interface
type ID = number | string;
interface Formatter {
  (input: string): string;
}
```

判断标识符用在哪一侧，看它出现的位置：类型注解的 `:` 之后、泛型实参、`as` 右侧、`implements` 之后属于类型位置；参与运算、赋值、调用的位置属于值位置。

```ts
const n = count; // 值位置
const id: ID = 1; // 类型位置
const fn = format as Formatter; // 两侧同时出现
```

类型位置唯一能读取值空间声明的运算符是 `typeof`，它把值的类型提取出来：

```ts
const config = { port: 8080 };

type Config = typeof config; // { port: number }
```

同名声明可以分别落在两侧而不冲突，因为两个命名空间之间互不查找：

```ts
interface Payload {
  id: number;
}

const Payload = {
  empty: { id: 0 } as Payload,
};
```

#### 6.2 一个类，三份声明

```ts
class User {
  static total = 0;

  constructor(public name: string) {
    User.total += 1;
  }

  greet(): string {
    return `hi ${this.name}`;
  }
}
```

一次 `class` 声明实际产生三份声明：类型空间中的实例类型 `User`，值空间中的构造函数 `User`，以及挂在构造函数上的静态成员。

| 写法                | 使用的声明             | 得到的类型                                    |
| ------------------- | ---------------------- | --------------------------------------------- |
| `let u: User`       | 类型空间               | `{ name: string; greet(): string }`           |
| `new User("Mimas")` | 值空间                 | `User`                                        |
| `User.total`        | 值空间                 | `number`                                      |
| `typeof User`       | 值空间取值，再转为类型 | `{ new (name: string): User; total: number }` |

由此可以划出两个方向的边界：类型注解中的 `User` 永远是实例类型，不含静态成员；要表达类本身，必须写 `typeof User`。

```ts
const user: User = new User("Mimas"); // OK
const ctor: typeof User = User; // OK
const wrong: User = User; // Error: typeof User 缺少 name 与 greet
user.total; // Error: 实例类型上没有 total
```

上表针对类声明。类表达式只写入值空间，因此不能直接当作类型使用：

```ts
const Admin = class {
  constructor(public level: number) {}
};

let a: Admin; // Error: Admin 只作为值存在
type AdminInstance = InstanceType<typeof Admin>; // OK: { level: number }
```

#### 6.3 类型侧擦除，值侧保留

```ts
class User {
  constructor(public name: string) {}

  greet(): string {
    return `hi ${this.name}`;
  }
}

const user: User = new User("Mimas");
```

编译后（示意）：

```js
class User {
  constructor(name) {
    this.name = name;
  }

  greet() {
    return `hi ${this.name}`;
  }
}

const user = new User("Mimas");
```

类型注解 `: User` 消失，构造函数与原型方法保留。这解释了 `instanceof` 为什么可行：它检查的是值空间里的构造函数，与类型声明无关。

```ts
const user = new User("Mimas");

console.log(user instanceof User); // true：运行时比较构造函数的原型链
```

#### 6.4 接口与类型别名只有类型侧

`interface` 与 `type` 不写入值空间，因此不能出现在需要值的位置：

```ts
interface Shape {
  area(): number;
}

const square: Shape = { area: () => 1 }; // OK：只做结构检查
new Shape(); // Error: Shape 没有值声明
```

类可以再声明一个同名接口来扩展实例类型，这是两侧能够互相补充的唯一组合：

```ts
class Point {
  constructor(
    public x: number,
    public y: number
  ) {}
}

interface Point {
  label: string;
}

const point = new Point(1, 2);
```

此时 `Point` 的实例类型包含 `label`，但类并未实现该字段，运行时取值是 `undefined`。这种合并需要自行保证成员真的被赋值，否则类型声明与运行时状态不一致。

#### 6.5 枚举的双侧声明

```ts
enum Status {
  Idle,
  Running,
}

let current: Status = Status.Running; // 类型位置用 Status，值位置也用 Status
```

类型侧 `Status` 是所有成员的联合；值侧 `Status` 是编译产物里的对象：

```js
var Status;
(function (Status) {
  Status[(Status["Idle"] = 0)] = "Idle";
  Status[(Status["Running"] = 1)] = "Running";
})(Status || (Status = {}));
```

反向映射只存在于数字枚举，字符串枚举不会生成 `"Idle": 0` 这一项。`const enum` 则在编译期把成员替换为字面量，不产出对象，值侧因此不可访问：

```ts
const enum Direction {
  Up,
  Down,
}

const d = Direction.Up; // 编译为 const d = 0
```

类的类型声明回答「这个变量是不是该类的实例」，值声明回答「如何构造实例、有哪些静态成员」；枚举的类型声明回答「这个变量是不是某个成员」，值声明回答「成员对应的运行时值」。两者同名共存，才使 `let current: Status = Status.Running` 在一行内同时完成类型约束与取值。

### 7. 多态

多态指同一操作作用于不同类型时给出不同行为。TypeScript 中有两条实现路径：子类型多态依靠继承与接口实现，在运行时按实例类型分派；参数化多态依靠泛型，在编译期把类型作为参数传入。前者的机制已在继承、接口与结构化类型三节展开，本节聚焦泛型的作用域、接口绑定及其与子类型多态的分工。

#### 7.1 泛型的两种作用域

泛型参数可以绑定在类或接口上，供全部成员共享；也可以只绑定在单个方法上，随调用独立推断。

```ts
class MyMap<K, V> {
  private entries = new Map<K, V>();

  get(key: K): V | undefined {
    return this.entries.get(key);
  }

  set(key: K, value: V): void {
    this.entries.set(key, value);
  }

  merge<K1, V1>(other: MyMap<K1, V1>): MyMap<K | K1, V | V1> {
    const merged = new MyMap<K | K1, V | V1>();
    this.entries.forEach((value, key) => merged.set(key, value));
    other.entries.forEach((value, key) => merged.set(key, value));
    return merged;
  }
}
```

`K`、`V` 在类声明处绑定，所有成员方法共享；`K1`、`V1` 只属于 `merge`，每次调用时从实参推断。返回类型 `MyMap<K | K1, V | V1>` 表示合并后键值范围扩大，原映射与传入映射的键值都落在新类型内。

```ts
const a = new MyMap<string, number>();
const b = new MyMap<number, boolean>();

const merged = a.merge(b); // MyMap<string | number, number | boolean>
```

#### 7.2 泛型接口与实现

接口同样可以在定义处绑定泛型。实现类需要补全类型实参，或者把类型参数继续向下传递：

```ts
interface User {
  id: string;
  name: string;
}

interface Repository<T> {
  find(id: string): T | undefined;
  save(entity: T): void;
}

class UserRepository implements Repository<User> {
  private users = new Map<string, User>();

  find(id: string): User | undefined {
    return this.users.get(id);
  }

  save(entity: User): void {
    this.users.set(entity.id, entity);
  }
}
```

`implements Repository<User>` 使类成员按 `T = User` 展开后逐项比对。若实现需要保留泛型，则写成 `class InMemoryRepository<T extends { id: string }> implements Repository<T>`，类型参数从类声明传递到接口，约束 `extends { id: string }` 保证 `save` 内部能访问 `entity.id`。

如果接口与类同名，两者会按 4.1 的规则声明合并，类型参数列表必须完全一致（名称与约束都要相同），上面示例使用不同名称是为了把两段声明分开。

#### 7.3 两条路径的分工

| 维度     | 子类型多态               | 参数化多态（泛型）                 |
| -------- | ------------------------ | ---------------------------------- |
| 实现方式 | `extends` / `implements` | 类型参数 `T`                       |
| 分派时机 | 运行时按实例类型分派方法 | 编译期代入类型，运行时擦除         |
| 类型关系 | is-a，受单继承限制       | 对任意类型成立，可多参数并带约束   |
| 复用内容 | 复用父类或抽象类的实现   | 复用类型关系，成员实现仍需各自提供 |

### 8. 混入

JavaScript 与 TypeScript 都没有 `trait` / `mixin` 关键字。它们不是语言级特性，而是一类用现有语法模拟多重继承（一个类同时获得多个来源的行为）的写法，常见于面向角色（Role-Oriented Programming，ROP）的设计中。

相较于mixin，trait（性状）没有构造方法，也不支持实例属性。不会在多个性状访问性状与基类的共用状态时产生冲突。

> [!note]
> 面向角色：着重描述类的行为，而不是它的属性。
>
> - 角色类（Role Class）：对角色的抽象描述，定义了该角色特有的属性和方法。
> - 角色组合（Role Composition）：允许将不同的角色组合在一起，形成一个更复杂的实体，从而实现更高层次的功能。
> - 角色协议（Role Protocol）：定义了角色之间的通信和协作方式，规定了消息传递和响应的规则。
> - 动态性：相比于传统 OOP 中类结构的相对固定，面向角色的系统通常支持动态创建、绑定和销毁角色，这使得系统能够根据环境变化灵活调整行为。

TypeScript 中最常用的是「类混入」：写一个函数，接收一个基类，返回一个继承该基类的匿名子类，把额外行为加在这个子类上。它具有以下特性：

- 可以有状态：混入产生的子类可以声明自己的实例属性。
- 只能提供具体方法：混入里写的是真实实现，不能像抽象类那样只声明抽象方法。
- 可以有构造方法：通过 `super(...args)` 把参数转交给基类；多个混入串联时，构造流程沿 `super()` 链自基类向外层依次执行。

下面的示例为任意带有 `getDebugValue()` 方法的类追加一个 `debug()` 方法。

```ts
// ClassConstructor<T> 描述「一个可以用任意参数 new 出来、产物类型为 T 的构造器」。
// 用 new (...args: any[]) => T 表达构造签名，稍后用它约束混入的目标类。
type ClassConstructor<T> = new (...args: any[]) => T;

// mixinEZDebug 是一个混入函数（高阶函数）：
// 输入基类 Base，输出一个继承 Base 的匿名子类，并在子类上追加 debug() 方法。
function mixinEZDebug<
  // 约束：Base 必须是构造器，且它 new 出的实例上必须有 getDebugValue()。
  // 有了这条约束，下面 this.getDebugValue() 才能在类型层面成立。
  T extends ClassConstructor<{ getDebugValue: () => object }>,
>(Base: T) {
  // 返回匿名子类：它继承 Base，因此拥有 Base 的全部成员，再叠加 debug。
  return class extends Base {
    constructor(...args: any[]) {
      // 派生类构造器必须先调用 super 才能访问 this；
      // ...args 把调用方传入的参数原样转交给 Base 的构造器。
      super(...args);
    }

    debug(): string {
      // 取原始类名：Base 就是被混入的那个类（例如 DebugNormalUser）。
      // 不能写成 Base.constructor.name——那是 Function，构造器函数自身的构造函数。
      const name = Base.name;
      // 调用约束里声明的 getDebugValue()，拿到需要序列化的数据。
      const value = this.getDebugValue();
      // 拼成「类名:JSON」的形式返回。
      return `${name}:` + JSON.stringify(value);
    }
  };
}

// 被混入的普通类：只要实例上有 getDebugValue()，就能作为 mixinEZDebug 的输入。
class DebugNormalUser {
  constructor(
    public id: string,
    private name: string
  ) {}

  getDebugValue() {
    return {
      id: this.id,
      name: this.name,
    };
  }
}

// mixinEZDebug 返回一个新的类：既有 DebugNormalUser 的成员，又有 debug()。
const User = mixinEZDebug(DebugNormalUser);
// 构造参数签名被保留，仍然是 (id: string, name: string)。
const user = new User("123", "mimas");

user.debug(); // DebugNormalUser:{"id":"123","name":"mimas"}
```

几点说明：

- `mixinEZDebug` 不修改 `DebugNormalUser` 本身，而是产出一个新的子类；原类保持独立，可被多处按不同方式混入。
- 泛型约束 `{ getDebugValue: () => object }` 只要求实例上有这个方法，因此任何满足该形状的类都能复用这段调试逻辑。
- `debug()` 中的 `Base.name` 指向被混入的原始类名；若写成 `Base.constructor.name`，取到的是 `Function`，与预期不符。
- 多个混入可以串联，例如 `mixinA(mixinB(Base))`：每一层都是「继承上一层、再追加方法」，构造时沿 `super()` 链从内层基类向外层执行。

### 9. 装饰器

装饰器本质是一个特殊函数，用于在不修改类本身的前提下，为类、属性、方法、访问器、参数追加横切逻辑（日志、校验、依赖注入等）。它把这类通用关注点从类内部抽离出来，业务代码保持原样。

TypeScript 有两套装饰器实现，签名不同，不能混用：

> [!note]
>
> - **传统装饰器（legacy）**：需要 `"experimentalDecorators": true`。Angular、NestJS、TypeORM 等存量项目使用这套，支持参数装饰器与 `emitDecoratorMetadata`。
> - **标准装饰器（TS 5.0 起，stage 3）**：默认启用，不要再开 `experimentalDecorators`（开启后反而回到 legacy 模式）。第二个参数是 `context` 对象，不支持参数装饰器。

9.1–9.7 均为传统装饰器，需要在 `tsconfig.json` 中开启：

```json
{
  "compilerOptions": {
    "experimentalDecorators": true,
    "emitDecoratorMetadata": true
  }
}
```

`emitDecoratorMetadata` 让编译产物附带类型元数据，运行时还需要引入 `reflect-metadata` 才能读取；不需要元数据时可以不配。

`experimentalDecorators` 是 tsconfig 级的编译选项，同一次编译只能选一种模式，因此两套装饰器互斥：

- 调用约定不同：传统装饰器传 `(target, propertyKey, descriptor)` 或 `(target, propertyKey, parameterIndex)`，标准装饰器传 `(value, context)` 并靠返回值替换目标；编译器无法按单个 `@dec` 判断它属于哪一套。
- 降级产物不同：传统模式生成 `__decorate`、`__param`、`__metadata`，标准模式生成 `__esDecorate`、`__runInitializers`，初始化顺序的语义也不同。
- 类型定义互斥：两种模式暴露的装饰器类型（如 `MethodDecorator` 与 `MethodDecoratorContext`）签名不兼容，不能同时生效。

互斥只发生在同一次编译：不同包各自编译成普通 JS 后，运行时可以互相引用，不受影响。

新项目建议直接使用标准装饰器，不配置 `experimentalDecorators`。与传统装饰器的差异主要有：

- 第二个参数是 `context` 对象，包含 `kind`、`name`、`static`、`addInitializer` 等上下文信息，不再接收原型与属性描述符。
- 不支持参数装饰器：NestJS 的 `@Inject()` / `@Body()`、Angular 的构造函数注入都依赖它，这类框架只能继续使用传统装饰器。
- 没有自动类型元数据：标准模式不提供 `emitDecoratorMetadata` 的 `design:type`，TypeORM 这类靠它推断列类型的库无法迁移；需要类型信息时只能显式声明，或改用 schema-first 方案（如 Zod）。

#### 9.1 类装饰器

签名：`(target: Function) => Function | void`。`target` 是被装饰的类构造函数，装饰器在类定义时执行一次。

```ts
// 类装饰器：接收类构造函数，可读取或修改它
function Demo(target: Function) {
  console.log(target.toString());
}

@Demo
class Person {
  constructor(
    public name: string,
    public age: number
  ) {}
}
// @Demo 等价于 Demo(Person)：类定义完成后立即调用
```

返回值决定是否替换原类：

- 返回一个新类：新类替换原类，此后 `new Person()` 实际创建的是新类的实例。
- 返回 `void` / `undefined`：保留原类，只做副作用操作。

```ts
function test(target: Function) {
  // 返回新类，Bar 会被它替换
  return class {
    testFun() {
      console.log(1);
    }
  };
}

@test
class Bar {
  testFun() {
    console.log(2);
  }
}

new Bar().testFun(); // 1，而不是 2
```

常见用法是改写原型方法。下面的装饰器让实例的 `toString()` 直接输出 JSON：

```ts
// 在原型上重写 toString，所有实例共享
function CustomToString(target: Function) {
  target.prototype.toString = function () {
    return JSON.stringify(this);
  };
}

@CustomToString
class Person {
  constructor(
    public name: string,
    public age: number
  ) {}
}

const p = new Person("张三", 18);
String(p); // {"name":"张三","age":18}
```

替换原类时，TypeScript 不会自动把新类的成员合并到原类类型上，直接 `new` 出来的实例按原类声明推断，新增成员需要额外声明。下面的 `logTime` 为实例添加创建时间与读取方法，配合接口声明合并让 TS 识别新成员：

```ts
// 构造器类型：只能用 new 调用，参数任意，实例类型为 {}
type ConstructorType = new (...args: any[]) => {};

// 声明合并：把装饰器新增的成员补充到 Person 类型上
interface Person {
  getTime(): void;
}

// 返回一个继承原类的新类，从而替换被装饰的类
function logTime<T extends ConstructorType>(target: T) {
  return class extends target {
    createdTime: number;

    constructor(...args: any[]) {
      super(...args);
      this.createdTime = Date.now();
    }

    getTime() {
      console.log("实例创建时间：" + this.createdTime);
    }
  };
}

@logTime
class Person {
  constructor(
    public name: string,
    public age: number
  ) {}
}

const p = new Person("张三", 18);
p.getTime(); // 实例创建时间：<时间戳>
```

这里用 `ConstructorType` 而不是 `Function`：`Function` 涵盖普通函数、箭头函数等，并不保证能用 `new` 调用；`new (...args: any[]) => {}` 才精确表达「构造器」。

#### 9.2 装饰器工厂

普通装饰器不能直接传参。需要参数时，写一个返回装饰器的函数，即装饰器工厂：

```ts
// 普通装饰器：@logInfo 等价于 logInfo(Person)
// 装饰器工厂：@logInfo(3) 等价于 logInfo(3)(Person)
function logInfo(times: number) {
  return function (target: ConstructorType) {
    target.prototype.speakInfo = function (this: { name: string }) {
      for (let i = 0; i < times; i++) {
        console.log(`你好，我是${this.name}`);
      }
    };
  };
}

@logInfo(3)
class Person {
  constructor(public name: string) {}
}

new Person("张三").speakInfo(); // 输出 3 次
```

两种写法对照：

| 写法          | 实际调用             |
| ------------- | -------------------- |
| `@logInfo`    | `logInfo(Person)`    |
| `@logInfo(3)` | `logInfo(3)(Person)` |

`target.prototype` 的类型是 `any`，所以 `this` 需要显式标注为 `{ name: string }`，否则在 `noImplicitThis` 下会报错。

#### 9.3 装饰器组合与执行顺序

多个装饰器可以叠加，规则如下：

- 装饰器表达式**自上而下**求值：工厂先被调用，拿到返回的装饰器函数。
- 装饰器函数**自下而上**应用。

```ts
function test1(target: Function) {
  console.log("test1");
}

function test2() {
  console.log("test2 工厂");
  return function (target: Function) {
    console.log("test2");
  };
}

function test3() {
  console.log("test3 工厂");
  return function (target: Function) {
    console.log("test3");
  };
}

function test4(target: Function) {
  console.log("test4");
}

@test1
@test2()
@test3()
@test4
class Person {}

// 输出顺序：
// test2 工厂
// test3 工厂
// test4
// test3
// test2
// test1
```

把三种写法组合起来时，返回新类的装饰器负责替换类，只改原型的装饰器负责补充方法，二者都在同一套声明合并类型上生效：

```ts
type Constructor = new (...args: any[]) => {};

interface Person {
  introduce(): void;
  logCreatedTime(): void;
}

// 改写原型上的 toString
function logToString(target: Constructor) {
  target.prototype.toString = function () {
    return JSON.stringify(this);
  };
}

// 返回新类并记录实例创建时间
function logTime<T extends Constructor>(target: T) {
  return class extends target {
    createdTime: number;

    constructor(...args: any[]) {
      super(...args);
      this.createdTime = Date.now();
    }

    logCreatedTime() {
      console.log("实例创建时间：", this.createdTime);
    }
  };
}

// 工厂：自我介绍 n 次
function logIntroduce(n: number) {
  return function (target: Constructor) {
    target.prototype.introduce = function (this: {
      name: string;
      age: number;
    }) {
      for (let i = 0; i < n; i++) {
        console.log(`我是${this.name}，今年${this.age}岁`);
      }
    };
  };
}

@logToString
@logIntroduce(5)
@logTime
class Person {
  constructor(
    public name: string,
    public age: number
  ) {}
}

const p = new Person("张三", 18);
p.introduce(); // 5 次自我介绍
p.logCreatedTime();
p.toString(); // {"name":"张三","age":18,"createdTime":...}
```

#### 9.4 属性装饰器

签名：`(target: object, propertyKey: string) => void`。属性装饰器只能读取元信息，拿不到属性描述符，不能直接修改属性值。

- 实例属性：`target` 是类的原型。
- 静态属性：`target` 是类构造函数。

```ts
function Demo(target: object, propertyKey: string) {
  console.log("target:", target);
  console.log("propertyKey:", propertyKey);
}

class Person {
  @Demo name: string;
  age: number;
  @Demo static school: string;

  constructor(name: string, age: number) {
    this.name = name;
    this.age = age;
  }
}
// name：target 为 Person.prototype
// school：target 为 Person 构造函数
```

属性装饰器的典型用途是把属性登记进元数据，供依赖注入容器读取，而不是直接赋值。另外，原型上的属性会被实例上的同名属性遮蔽，两者无法同时访问，这一点与装饰器无关。

#### 9.5 方法装饰器

签名：`(target: object, propertyKey: string, descriptor: PropertyDescriptor) => void | PropertyDescriptor`。

- `target`：静态方法为类构造函数，实例方法为类原型。
- `propertyKey`：方法名。
- `descriptor`：属性描述符，`descriptor.value` 就是方法本身，可整体替换。

```ts
function logger(
  target: object,
  propertyKey: string,
  descriptor: PropertyDescriptor
) {
  // 保存原方法
  const original = descriptor.value;
  // 用新函数替换，加入前后置日志
  descriptor.value = function (...args: any[]) {
    console.log(`${target.constructor.name}-${propertyKey} start`);
    const result = original.call(this, ...args);
    console.log(`${target.constructor.name}-${propertyKey} end`);
    return result;
  };
}

class Person {
  constructor(public name: string) {}

  @logger
  speak(str: string) {
    console.log(this.name, str);
  }
}

new Person("张三").speak("你好");
// Person-speak start
// 张三 你好
// Person-speak end
```

`original.call(this, ...args)` 保证 `this` 仍指向调用方实例；若写成 `original(...args)`，方法内部访问 `this` 会丢失上下文。

#### 9.6 访问器装饰器

签名与方法装饰器一致，`descriptor` 上是 `get` / `set`。同一个访问器只能装饰 get 或 set 其中之一。

```ts
function RangeValidate(min: number, max: number) {
  return function (
    target: object,
    propertyKey: string,
    descriptor: PropertyDescriptor
  ) {
    // 保存原始 setter
    const originalSetter = descriptor.set;
    // 覆盖 setter：先校验，再转交原实现
    descriptor.set = function (newVal: number) {
      if (newVal < min || newVal > max) {
        throw new Error(`温度必须在 ${min} 到 ${max} 之间`);
      }
      originalSetter?.call(this, newVal);
    };
    return descriptor;
  };
}

class Weather {
  private _temp: number;

  constructor(temp: number) {
    this._temp = temp;
  }

  get temp() {
    return this._temp;
  }

  @RangeValidate(0, 55)
  set temp(newVal: number) {
    this._temp = newVal;
  }
}

const w = new Weather(22);
w.temp = 30; // 通过
// w.temp = 80; // 抛出 Error: 温度必须在 0 到 55 之间
```

#### 9.7 参数装饰器

签名：`(target: object, propertyKey: string, parameterIndex: number) => void`，`parameterIndex` 是参数下标（从 0 开始）。参数装饰器只存在于传统装饰器，标准装饰器不支持。

```ts
function ParamDemo(
  target: object,
  propertyKey: string,
  parameterIndex: number
) {
  console.log(propertyKey, parameterIndex);
}

class Person {
  greet(@ParamDemo message: string) {
    return message;
  }
}

// 输出：greet 0
```

参数装饰器不能改变参数值，通常配合 `reflect-metadata` 记录依赖信息，供依赖注入容器读取，NestJS 的 `@Inject` 就是这种用法。

#### 9.8 标准装饰器（TS 5.0+）

标准装饰器的第一个参数是被装饰的值，第二个参数是 `context` 对象（包含 `kind`、`name`、`addInitializer` 等），不再接收原型和属性描述符。

```ts
function Log<T extends abstract new (...args: any[]) => any>(
  target: T,
  context: ClassDecoratorContext<T>
) {
  console.log(`Decorating ${String(context.name)}`);
  return target;
}

@Log
class Service {}
```

两套装饰器的差异：

| 维度       | 传统装饰器                     | 标准装饰器           |
| ---------- | ------------------------------ | -------------------- |
| 开启方式   | `experimentalDecorators: true` | 默认启用，无需该标记 |
| 第二参数   | 无（类装饰器只收 `Function`）  | `context` 对象       |
| 参数装饰器 | 支持                           | 不支持               |
| 类型元数据 | 可用 `emitDecoratorMetadata`   | 不提供               |
| 常见使用者 | Angular / NestJS / TypeORM     | 原生 stage 3 项目    |

维护存量项目时按传统装饰器理解；新项目可以直接使用 TS 5 的标准装饰器。

### 10. 模拟 final 类

Java 等语言的 `final` 修饰符用于将类标记为不可扩展，或将方法标记为不可覆盖。TypeScript 不提供 `final`，只能通过 `private constructor` 在类型层面模拟。

#### 10.1 私有构造函数阻止继承

```ts
class MessageQueue {
  private constructor() {
    // ...
  }
}

class A extends MessageQueue {} // Error: Cannot extend a class 'MessageQueue'. Class constructor is marked as private.
new MessageQueue(); // Error: Constructor of class 'MessageQueue' is private.
```

子类的构造函数必须调用 `super()`，而私有构造函数对其他类不可见，`extends` 因此在编译期报错；同一限制也使外部无法直接 `new` 出实例。

> [!note]
> 该约束只作用于类型检查。使用 `// @ts-expect-error`、类型断言或纯 JavaScript 调用时，仍可绕过限制完成继承与实例化。

#### 10.2 私有构造函数配合静态工厂

完全禁止实例化会让类失去用途，常见做法是保留一个静态工厂方法，由类自身控制实例创建。

```ts
class MessageQueue {
  private constructor(private messages: string[]) {}

  static create(messages: string[]) {
    return new MessageQueue(messages);
  }

  get size() {
    return this.messages.length;
  }
}

const queue = MessageQueue.create(["a", "b"]); // ok
```

静态成员属于类本身，可以访问私有构造函数，因此 `create` 能正常返回实例；外部调用方只能通过工厂获取对象，既保留不可继承性，又提供受控的实例化入口。参数校验、实例缓存等逻辑也可以集中放在工厂中。

该技巧只约束继承与构造入口，无法约束方法级覆盖；需要禁止覆盖时，只能依靠命名约定或文档约束。

### 11. 设计模式

#### 11.1 工厂模式

工厂模式把对象的创建过程从调用方抽离：调用方不直接 `new` 具体类，而是把创建参数交给工厂，由工厂决定返回哪个实现。工厂的返回类型是公共接口，调用方只依赖接口，新增实现时只需修改工厂内部。

```ts
interface Logger {
  log(message: string): void;
}

class ConsoleLogger implements Logger {
  log(message: string) {
    console.log(message);
  }
}

class FileLogger implements Logger {
  log(message: string) {
    // write to file ...
  }
}

type LoggerType = "console" | "file";

function createLogger(type: LoggerType): Logger {
  return type === "console" ? new ConsoleLogger() : new FileLogger();
}

const logger = createLogger("console");
logger.log("hello");
```

`createLogger` 是工厂函数，调用方只知道 `Logger` 接口，无需关心 `ConsoleLogger` 与 `FileLogger` 的构造细节。

工厂函数与函数重载容易混淆，区别在于：

- 重载是编译期的签名声明，运行时只有一个函数体，由参数类型决定匹配的签名与返回类型；工厂在运行期根据参数值创建不同实例。
- 重载不涉及对象创建；工厂承担构造逻辑，如参数校验、实例缓存。
- 工厂返回统一接口，具体类型对调用方不可见；需要精确返回类型时，可以给工厂补充重载签名。

```ts
function createLogger(type: "console"): ConsoleLogger;
function createLogger(type: "file"): FileLogger;
function createLogger(type: LoggerType): Logger {
  return type === "console" ? new ConsoleLogger() : new FileLogger();
}

const c = createLogger("console"); // ConsoleLogger
```

#### 11.2 建造者模式

建造者模式把复杂对象的装配过程拆成若干步骤，每一步只设置一个属性并返回 `this`，最后由 `build()` 统一产出结果。它适用于构造参数多、可选参数组合多的场景，用于替代超长的构造函数参数列表。与工厂模式的区别在于：工厂决定创建哪个实现，建造者决定如何一步步组装同一个对象。

```ts
// 只靠类型限制调用顺序：运行时始终是同一个 TestBuilder 实例，阶段差异只体现在静态类型上。

// 第一阶段：url 尚未设置。
// 只暴露 setName / setOther，且它们返回的仍是 StepInit，因此此时没有 build
interface StepInit {
  setUrl(url: string): StepReady; // 调用后进入下一阶段
  setName(name: string): StepInit; // 与 setOther 顺序任意、可重复调用
  setOther(other: string): StepInit;
}

// 第二阶段：url 已设置，build 从这里才开始可见
interface StepReady {
  setName(name: string): StepReady;
  setOther(other: string): StepReady;
  build(): { url: string; name: string; other: string };
}

// 同一个实现类同时实现两个阶段的接口，方法统一 return this
class TestBuilder implements StepInit, StepReady {
  private url = "";
  private name = "";
  private other = "";

  // 返回类型写 this：运行时返回同一个对象；调用方看到的类型由接口声明决定
  setUrl(url: string): this {
    this.url = url;
    return this;
  }

  setName(name: string): this {
    this.name = name;
    return this;
  }

  setOther(other: string): this {
    this.other = other;
    return this;
  }

  build() {
    return { url: this.url, name: this.name, other: this.other };
  }
}

// 工厂只把 StepInit 暴露给外部，调用方拿不到 TestBuilder 的完整类型，无法跳过阶段
export function createBuilder(): StepInit {
  return new TestBuilder();
}

// 合法：setName / setOther 顺序任意，只要 setUrl 在 build 之前
const data = createBuilder()
  .setName("b")
  .setOther("o")
  .setUrl("https://www.baidu.com")
  .build();

// 报错：setName 之后仍是 StepInit 类型，没有 build
createBuilder().setName("b").build();

// 报错：初始阶段没有 build
createBuilder().build();
```

各步骤返回 `this`，链式调用结束后由 `build()` 读取累积状态生成最终结果。设置步骤与产出步骤分离，新增子句时只需增加一个方法，不影响已有调用链。
