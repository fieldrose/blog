前端每天都在用 `Array`、`Map`、`Set`，但很少有人关心它们的底层形态。判断一个操作是 O(1) 还是 O(n)，决定了在渲染循环里能不能安全调用。本文从复杂度讲起，逐个拆解线性结构与哈希表，并给出可运行的 TypeScript 实现。

## 一、复杂度与度量

### 1.1 时间复杂度

大 O 描述输入规模增长时耗时的上界，忽略常数与低阶项。

| 复杂度 | 常见来源 | 前端例子 |
| ------ | -------- | -------- |
| O(1) | 哈希查找、数组下标访问 | `map.get(key)`、`arr[i]` |
| O(log n) | 二分、平衡树、堆操作 | 有序列表定位、优先级队列 |
| O(n) | 一次遍历、链表查找 | `find`、`indexOf`、`shift` |
| O(n log n) | 归并、快排、堆排 | `Array.prototype.sort` |
| O(n²) | 双层循环、朴素去重 | 嵌套列表匹配 |

- 摊还复杂度用于描述偶发高成本、长期平均成本低的操作，动态数组 `push` 是典型。
- 空间复杂度同样要计入，哈希表用空间换时间，链表用指针换插入效率。
- 常数因子在真实场景中不可忽略，O(n) 的数组遍历通常快于 O(log n) 的树查找，因为前者内存连续、缓存友好。

### 1.2 JavaScript 数组的真实成本

| 操作 | 复杂度 | 说明 |
| ---- | ------ | ---- |
| `arr[i]` | O(1) | 快速路径下是连续内存寻址 |
| `push` / `pop` | O(1) 摊还 | 扩容时一次性搬移 |
| `shift` / `unshift` | O(n) | 需要整体前移或后移 |
| `splice` | O(n) | 删除或插入点之后都要移动 |
| `includes` / `indexOf` | O(n) | 线性扫描 |
| `sort` | O(n log n) | 现代 V8 使用 TimSort |

- `shift` 在循环中调用会退化为 O(n²)，长列表处理应改用索引游标或环形队列。
- 稀疏数组与混合类型会让 V8 的数组从快速模式退化为字典模式，访问成本上升。
- 判断性能问题时，先看操作复杂度，再看引擎优化，顺序反了会陷入微基准。

## 二、数组

### 2.1 连续存储与随机访问

数组用一段连续内存保存同尺寸元素，下标访问通过 `base + i * size` 直接定位地址。

- 连续内存带来良好的缓存局部性，顺序遍历远比随机跳转快。
- V8 为数组维护元素种类（elements kind），如 `PACKED_SMI_ELEMENTS`、`PACKED_DOUBLE_ELEMENTS`、`PACKED_ELEMENTS`。
- 元素种类只会向更通用的方向转换，写入浮点数或对象后不会退回整数模式。
- 出现空洞会转为 `HOLEY_*`，访问需要额外检查，通常比紧凑数组慢。

### 2.2 动态扩容与摊还成本

固定长度数组无法满足动态增长，实现上采用「容量不足时翻倍并复制」的策略。

```ts
class DynamicArray<T> {
  private data: Array<T | undefined> = new Array(4);
  private count = 0;

  get length(): number {
    return this.count;
  }

  get(index: number): T | undefined {
    if (index < 0 || index >= this.count) return undefined;
    return this.data[index];
  }

  push(value: T): void {
    if (this.count === this.data.length) {
      this.resize(this.data.length * 2);
    }
    this.data[this.count++] = value;
  }

  pop(): T | undefined {
    if (this.count === 0) return undefined;
    const value = this.data[--this.count];
    this.data[this.count] = undefined; // 释放引用，避免阻止 GC
    return value;
  }

  private resize(capacity: number): void {
    const next = new Array<T | undefined>(capacity);
    for (let i = 0; i < this.count; i++) next[i] = this.data[i];
    this.data = next;
  }
}
```

- 扩容成本为 O(n)，但发生在容量翻倍时，均摊到每次 `push` 是 O(1)。
- 缩容策略要保守，频繁在临界点增删会导致反复搬移。
- 复制是浅拷贝，元素为对象时只复制引用，不会深拷贝对象。

### 2.3 前端场景

- 列表渲染与批量处理优先使用数组，避免在渲染函数中做 O(n²) 的查找。
- 二进制数据使用 `ArrayBuffer` 与 `TypedArray`：`ImageData`、`WebGL` 顶点数据、音频采样都依赖定长连续内存。
- `TypedArray` 长度固定、无空洞、元素类型确定，适合数值密集型计算。
- 大数组分块处理，避免单次遍历阻塞主线程。

## 三、链表

### 3.1 结构与复杂度

链表由节点组成，每个节点保存值与下一个节点的引用，双链表额外保存前驱引用。

| 操作 | 数组 | 链表 |
| ---- | ---- | ---- |
| 随机访问 | O(1) | O(n) |
| 头部插入 | O(n) | O(1) |
| 已知节点后插入 | O(n) | O(1) |
| 删除已知节点 | O(n) | O(1)（双链表） |
| 内存开销 | 低 | 每节点额外指针 |

- 链表不要求连续内存，插入删除不需要搬移元素。
- 查找仍需遍历，因此「定位」成本没有降低，只是「修改」成本降低了。
- 节点分散在堆上，缓存局部性差，顺序遍历通常慢于数组。

### 3.2 前端场景

- React Fiber 用 `child`、`sibling`、`return` 三个指针把组件树串成链表，使遍历可中断、可恢复。
- 路由历史、撤销重做、编辑器操作记录本质是栈或双链表。
- 链表结构适合频繁在中间插入删除、但很少随机访问的场景。

```ts
class ListNode<T> {
  constructor(
    public value: T,
    public next: ListNode<T> | null = null,
    public prev: ListNode<T> | null = null,
  ) {}
}
```

## 四、栈与队列

### 4.1 栈

栈遵循后进先出，核心操作是 `push`、`pop`、`peek`。

- 调用栈是最典型的栈：函数调用压栈，返回弹栈，递归过深导致栈溢出。
- 括号匹配、表达式求值、撤销操作、DFS 的迭代实现都依赖栈。
- 用数组实现栈时，只在尾部操作，复杂度为 O(1)。

```ts
function isBalanced(input: string): boolean {
  const pairs: Record<string, string> = { ")": "(", "]": "[", "}": "{" };
  const stack: string[] = [];
  for (const char of input) {
    if (char === "(" || char === "[" || char === "{") {
      stack.push(char);
    } else if (pairs[char]) {
      if (stack.pop() !== pairs[char]) return false;
    }
  }
  return stack.length === 0;
}
```

### 4.2 队列与环形缓冲

队列遵循先进先出。数组 `shift` 是 O(n)，高频出队应使用头指针或环形缓冲。

```ts
class RingQueue<T> {
  private buffer: Array<T | undefined>;
  private head = 0;
  private tail = 0;
  private count = 0;

  constructor(capacity: number) {
    this.buffer = new Array(capacity);
  }

  enqueue(value: T): boolean {
    if (this.count === this.buffer.length) return false; // 队满
    this.buffer[this.tail] = value;
    this.tail = (this.tail + 1) % this.buffer.length;
    this.count++;
    return true;
  }

  dequeue(): T | undefined {
    if (this.count === 0) return undefined;
    const value = this.buffer[this.head];
    this.buffer[this.head] = undefined;
    this.head = (this.head + 1) % this.buffer.length;
    this.count--;
    return value;
  }
}
```

- 环形缓冲容量固定，溢出策略（丢弃最旧或拒绝写入）需要按业务选择。
- 浏览器的任务队列、消息队列、请求并发池都是队列模型。
- BFS 依赖队列，保证按层访问。

### 4.3 双端队列与单调队列

双端队列允许两端进出。单调队列在普通队列基础上维护元素单调性，用于滑动窗口最值。

```ts
function maxSlidingWindow(nums: number[], k: number): number[] {
  const result: number[] = [];
  const deque: number[] = []; // 存下标，对应值单调递减
  for (let i = 0; i < nums.length; i++) {
    while (deque.length && deque[0] <= i - k) deque.shift();
    while (deque.length && nums[deque[deque.length - 1]] <= nums[i]) deque.pop();
    deque.push(i);
    if (i >= k - 1) result.push(nums[deque[0]]);
  }
  return result;
}
```

- 单调队列每个元素最多进出各一次，整体 O(n)。
- 前端可用于滚动窗口内的性能统计、限流窗口、实时指标聚合。

## 五、哈希表

### 5.1 原理与冲突处理

哈希表通过哈希函数把键映射到桶下标，理想情况下查找为 O(1)。

- 哈希冲突无法避免，常见处理方式是链地址法（桶内挂链表）与开放寻址（线性探测、二次探测）。
- 负载因子等于元素数除以桶数，超过阈值（常见 0.75）触发扩容并重新散列。
- 最坏情况下所有键落在同一桶，退化为 O(n)。
- 哈希函数应分布均匀且计算廉价，字符串常用多项式滚动哈希。

```ts
class HashTable<K extends string, V> {
  private buckets: Array<Array<[K, V]>>;
  private size = 0;

  constructor(private capacity = 16) {
    this.buckets = Array.from({ length: capacity }, () => []);
  }

  private hash(key: K): number {
    let hash = 0;
    for (let i = 0; i < key.length; i++) {
      hash = (hash * 31 + key.charCodeAt(i)) | 0;
    }
    return Math.abs(hash) % this.buckets.length;
  }

  set(key: K, value: V): void {
    const bucket = this.buckets[this.hash(key)];
    const pair = bucket.find(([k]) => k === key);
    if (pair) {
      pair[1] = value;
      return;
    }
    bucket.push([key, value]);
    this.size++;
    if (this.size / this.buckets.length > 0.75) this.resize();
  }

  get(key: K): V | undefined {
    return this.buckets[this.hash(key)].find(([k]) => k === key)?.[1];
  }

  private resize(): void {
    const entries = this.buckets.flat();
    this.capacity *= 2;
    this.buckets = Array.from({ length: this.capacity }, () => []);
    this.size = 0;
    for (const [key, value] of entries) this.set(key, value);
  }
}
```

### 5.2 Object、Map 与 WeakMap

| 能力 | Object | Map | WeakMap |
| ---- | ------ | --- | ------- |
| 键类型 | 字符串与 Symbol | 任意类型 | 对象（含函数） |
| 插入顺序 | 字符串键有序 | 保证插入顺序 | 不可枚举 |
| 迭代 | `Object.keys` 等 | 可迭代 | 不可迭代 |
| 大小 | 需手动计算 | `size` | 无 |
| 键的回收 | 强引用 | 强引用 | 弱引用，可被 GC |

- `Object` 的键会被转换为字符串或 Symbol，数字键实际也是字符串。
- `Map` 以引用比较对象键，两个内容相同的对象是不同键。
- `WeakMap` 的键是弱引用，适合给 DOM 节点、组件实例挂载关联数据而不阻止回收。
- 频繁增删的字典优先用 `Map`，结构稳定的记录可用 `Object` 配合固定形状获得更好的属性访问优化。

### 5.3 前端场景

- 路由表、权限映射、国际化词条、组件注册表都是字典结构。
- 去重与计数使用 `Set`、`Map`，比数组 `includes` 的 O(n²) 更稳。
- 缓存键需要可控的序列化规则，对象直接转字符串可能产生冲突。
- `WeakMap` 可用于事件委托中的节点状态、依赖收集中的对象关联。

## 六、选型对照

| 结构 | 访问 | 插入 | 删除 | 典型用途 |
| ---- | ---- | ---- | ---- | -------- |
| 数组 | O(1) | 尾部 O(1) 摊还 | 中间 O(n) | 列表渲染、批量数据 |
| 链表 | O(n) | O(1) | O(1) | Fiber 遍历、撤销栈 |
| 栈 | 栈顶 O(1) | O(1) | O(1) | 调用栈、括号匹配、DFS |
| 队列 | 队首 O(1) | O(1) | O(1) | 任务调度、BFS、并发池 |
| 哈希表 | O(1) 平均 | O(1) 平均 | O(1) 平均 | 缓存、映射、去重 |

选型时先确定访问模式，再比较复杂度，最后用真实数据验证。数据结构没有绝对优劣，只有与场景是否匹配。
