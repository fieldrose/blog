模块依赖、构建流水线、权限继承、接口缓存，这些问题在数据结构层面都指向图与查找算法。本文给出图的表示与遍历、拓扑排序与并查集，再补上排序、二分与缓存淘汰，最后讨论工程中的取舍。

## 一、图的表示与遍历

### 1.1 邻接表与邻接矩阵

| 表示 | 空间 | 判断边 | 遍历邻居 | 适用 |
| ---- | ---- | ------ | -------- | ---- |
| 邻接矩阵 | O(n²) | O(1) | O(n) | 稠密图、频繁判断连通 |
| 邻接表 | O(n + m) | O(degree) | O(degree) | 稀疏图、遍历为主 |

```ts
class Graph {
  private adjacency = new Map<string, string[]>();

  addVertex(vertex: string): void {
    if (!this.adjacency.has(vertex)) this.adjacency.set(vertex, []);
  }

  addEdge(from: string, to: string): void {
    this.addVertex(from);
    this.addVertex(to);
    this.adjacency.get(from)!.push(to);
  }

  neighbors(vertex: string): string[] {
    return this.adjacency.get(vertex) ?? [];
  }

  get vertices(): string[] {
    return [...this.adjacency.keys()];
  }
}
```

- 有向图只在起点侧添加边，无向图需要双向添加。
- 带权图把邻居存为 `{ to, weight }`，或使用邻接矩阵保存权重。
- 前端场景中的图通常稀疏，邻接表更常见。

### 1.2 BFS 与 DFS

```ts
function bfs(graph: Graph, start: string): string[] {
  const visited = new Set<string>([start]);
  const queue: string[] = [start];
  const order: string[] = [];

  while (queue.length) {
    const vertex = queue.shift()!;
    order.push(vertex);
    for (const next of graph.neighbors(vertex)) {
      if (visited.has(next)) continue;
      visited.add(next);
      queue.push(next);
    }
  }
  return order;
}

function dfs(graph: Graph, start: string): string[] {
  const visited = new Set<string>();
  const stack = [start];
  const order: string[] = [];

  while (stack.length) {
    const vertex = stack.pop()!;
    if (visited.has(vertex)) continue;
    visited.add(vertex);
    order.push(vertex);
    for (const next of graph.neighbors(vertex)) {
      if (!visited.has(next)) stack.push(next);
    }
  }
  return order;
}
```

- BFS 按层扩展，无权图上的最短路径就是首次到达的层数。
- DFS 适合连通分量、环检测与路径枚举。
- 遍历必须维护 `visited`，否则有环图会死循环。
- 用数组 `shift` 实现 BFS 队列是 O(n)，大规模图应换成头指针或环形队列。

### 1.3 拓扑排序

拓扑排序把有向无环图排成线性序列，保证每条边的起点都在终点之前。Kahn 算法基于入度：

```ts
function topologicalSort(graph: Graph): string[] | null {
  const indegree = new Map<string, number>();
  for (const vertex of graph.vertices) indegree.set(vertex, 0);
  for (const vertex of graph.vertices) {
    for (const next of graph.neighbors(vertex)) {
      indegree.set(next, (indegree.get(next) ?? 0) + 1);
    }
  }

  const queue = graph.vertices.filter((vertex) => indegree.get(vertex) === 0);
  const order: string[] = [];

  while (queue.length) {
    const vertex = queue.shift()!;
    order.push(vertex);
    for (const next of graph.neighbors(vertex)) {
      const degree = indegree.get(next)! - 1;
      indegree.set(next, degree);
      if (degree === 0) queue.push(next);
    }
  }

  return order.length === graph.vertices.length ? order : null; // null 表示存在环
}
```

- 入度为 0 的节点可以安全执行，执行后删除其出边，重复该过程。
- 结果长度小于节点数说明存在环，可用于检测循环依赖。
- 前端场景：构建顺序、任务编排、monorepo 包依赖、CI 阶段依赖、表单联动规则。

### 1.4 最短路径与并查集

- Dijkstra 用于非负权图，配合最小堆每次取出当前距离最小的节点，复杂度 O((n + m) log n)。
- Bellman-Ford 支持负权边并能检测负环，复杂度 O(nm)。
- 无权图直接用 BFS，不需要 Dijkstra。
- 并查集维护不相交集合，支持合并与连通性查询，配合路径压缩与按秩合并后接近 O(1)。

```ts
class UnionFind {
  private parent = new Map<string, string>();
  private rank = new Map<string, number>();

  find(x: string): string {
    let root = x;
    while (this.parent.get(root) && this.parent.get(root) !== root) {
      root = this.parent.get(root)!;
    }
    // 路径压缩：把沿途节点直接挂到根上
    let current = x;
    while (current !== root) {
      const next = this.parent.get(current)!;
      this.parent.set(current, root);
      current = next;
    }
    return root;
  }

  union(a: string, b: string): boolean {
    const rootA = this.find(a);
    const rootB = this.find(b);
    if (rootA === rootB) return false;
    const rankA = this.rank.get(rootA) ?? 0;
    const rankB = this.rank.get(rootB) ?? 0;
    if (rankA < rankB) this.parent.set(rootA, rootB);
    else if (rankA > rankB) this.parent.set(rootB, rootA);
    else {
      this.parent.set(rootB, rootA);
      this.rank.set(rootA, rankA + 1);
    }
    return true;
  }
}
```

- 并查集适合动态连通性问题，如权限组合并、账号归并、网络节点分组。
- 前端场景中，配置继承与权限继承也可以建模为图，用并查集或树形合并求解。

## 二、排序

### 2.1 稳定性与下界

- 稳定排序保证相等元素的相对顺序不变，多字段排序依赖这一性质。
- 基于比较的排序下界是 O(n log n)，计数排序、桶排序在值域有限时可达到 O(n)。
- 原地排序节省内存，非原地排序（归并）需要 O(n) 额外空间。

### 2.2 常见算法对照

| 算法 | 平均 | 最坏 | 空间 | 稳定 |
| ---- | ---- | ---- | ---- | ---- |
| 冒泡 | O(n²) | O(n²) | O(1) | 稳定 |
| 插入 | O(n²) | O(n²) | O(1) | 稳定 |
| 选择 | O(n²) | O(n²) | O(1) | 不稳定 |
| 归并 | O(n log n) | O(n log n) | O(n) | 稳定 |
| 快速 | O(n log n) | O(n²) | O(log n) | 不稳定 |
| 堆排序 | O(n log n) | O(n log n) | O(1) | 不稳定 |

```ts
function quickSort<T>(items: T[], compare: (a: T, b: T) => number): T[] {
  if (items.length <= 1) return items;
  const pivot = items[Math.floor(items.length / 2)];
  const left: T[] = [];
  const middle: T[] = [];
  const right: T[] = [];

  for (const item of items) {
    const diff = compare(item, pivot);
    if (diff < 0) left.push(item);
    else if (diff > 0) right.push(item);
    else middle.push(item);
  }
  return [...quickSort(left, compare), ...middle, ...quickSort(right, compare)];
}
```

- 快速排序在近乎有序的数据上若固定取首元素为基准，会退化为 O(n²)，随机基准或三数取中可以缓解。
- 归并排序稳定且最坏也是 O(n log n)，代价是额外空间。
- `Array.prototype.sort` 自 ES2019 起要求稳定，V8 使用 TimSort，对部分有序数据接近 O(n)。

### 2.3 前端场景

```js
[10, 9, 1].sort(); // [1, 10, 9]，默认按字符串比较
[10, 9, 1].sort((a, b) => a - b); // [1, 9, 10]
```

- 默认比较会把元素转成字符串，数值排序必须传比较函数。
- 表格多列排序依赖稳定性：先按次关键字排序，再按主关键字排序。
- 只需要前 K 个结果时用堆，不必全量排序。
- 大数组排序会阻塞主线程，可拆分到 Worker 或使用分块归并。

## 三、查找

### 3.1 二分查找与边界

```ts
function lowerBound<T>(items: T[], target: T, compare: (a: T, b: T) => number): number {
  let low = 0;
  let high = items.length;
  while (low < high) {
    const mid = (low + high) >> 1;
    if (compare(items[mid], target) < 0) low = mid + 1;
    else high = mid;
  }
  return low;
}
```

- `lowerBound` 返回第一个不小于目标的位置，`upperBound` 返回第一个大于目标的位置。
- 用 `[low, high)` 半开区间书写，可以避免大量边界错误。
- 二分要求数据有序，插入频繁时维护有序数组的成本可能高于收益。
- 前端用于有序列表定位、时间轴定位、虚拟列表按滚动位置反查起始索引。

### 3.2 其他查找结构

- 哈希查找 O(1)，适合精确匹配，不支持范围查询。
- 跳表用多层索引实现有序链表的 O(log n) 查找，Redis 的有序集合使用该结构。
- 平衡树支持范围查询与顺序遍历，代价是实现复杂度更高。

## 四、缓存淘汰

### 4.1 常见策略

| 策略 | 淘汰依据 | 优点 | 缺点 |
| ---- | -------- | ---- | ---- |
| FIFO | 进入顺序 | 实现简单 | 可能淘汰热点数据 |
| LRU | 最近使用时间 | 贴合时间局部性 | 偶发批量扫描会污染缓存 |
| LFU | 使用频率 | 保留长期热点 | 新数据难以进入，需要衰减 |
| TTL | 过期时间 | 控制数据新鲜度 | 与容量无关，可能同时失效 |

### 4.2 LRU 实现

```ts
class LRUCache<K, V> {
  private store = new Map<K, V>();

  constructor(private capacity: number) {}

  get(key: K): V | undefined {
    if (!this.store.has(key)) return undefined;
    const value = this.store.get(key)!;
    this.store.delete(key); // 删除后重新插入，移动到队尾
    this.store.set(key, value);
    return value;
  }

  set(key: K, value: V): void {
    if (this.store.has(key)) this.store.delete(key);
    else if (this.store.size >= this.capacity) {
      const oldest = this.store.keys().next().value as K;
      this.store.delete(oldest);
    }
    this.store.set(key, value);
  }
}
```

- `Map` 迭代顺序等于插入顺序，因此可以省去手写双向链表。
- 严格意义上的 LRU 用哈希表加双向链表，`get` 与 `set` 都是 O(1)。
- 容量为 0 或负数时应直接跳过缓存，避免无限增长。
- LFU 需要维护频率桶或最小频率指针，实现复杂度明显高于 LRU。

### 4.3 前端缓存场景

- 接口缓存与请求去重：相同参数的请求在短时间内复用结果，并设置上限与 TTL。
- 图片与组件缓存：列表滚动回收后保留少量已渲染结果，避免重复计算。
- Service Worker 缓存策略：按资源类型选择 Cache First、Network First、Stale While Revalidate。
- 框架层缓存（如查询库）通常同时使用 TTL 与容量上限，避免只按时间淘汰导致内存膨胀。

## 五、复杂度与工程取舍

| 问题 | 推荐结构 | 复杂度 |
| ---- | -------- | ------ |
| 模块依赖顺序 | 图 + 拓扑排序 | O(n + m) |
| 动态连通性 | 并查集 | 近似 O(1) |
| 有序数据查找 | 二分 / 平衡树 | O(log n) |
| 前 K 个最值 | 堆 | O(n log K) |
| 热点数据缓存 | LRU / LFU | O(1) / O(log n) |

工程中优先选择实现简单、常数因子小的方案。复杂度只描述增长趋势，真实性能还要看数据规模、内存布局与调用频率，最终以 profile 结果为准。
